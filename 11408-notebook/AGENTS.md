## 三、追加规则（重要）

ipynb 本质是 JSON 文件。**nbformat 4.5+ 的每个 cell 必须有 `id` 字段**（8 位十六进制即可），否则 Jupyter 打开时会告警。结构如下：

```json
{
  "cells": [
    {"cell_type": "markdown", "id": "a1b2c3d4", "metadata": {}, "source": ["## 标题\n", "内容"]}
  ],
  "metadata": {},
  "nbformat": 4,
  "nbformat_minor": 5
}
```

**标准追加流程**（可直接照抄）：

```python
import json, uuid
from pathlib import Path

p = Path("notes/408/03-存储层次与Cache.ipynb")
if p.exists():
    nb = json.loads(p.read_text(encoding="utf-8"))
else:
    nb = {"cells": [], "metadata": {}, "nbformat": 4, "nbformat_minor": 5}

nb["cells"].append({
    "cell_type": "markdown",
    "id": uuid.uuid4().hex[:8],
    "metadata": {},
    "source": ["## 知识点名称\n", "\n", "> 2026-09-27 · 来源：学习对话\n", "- 内容1\n", "- 内容2"],
})
p.parent.mkdir(parents=True, exist_ok=True)
p.write_text(json.dumps(nb, ensure_ascii=False, indent=1) + "\n", encoding="utf-8")

json.loads(p.read_text(encoding="utf-8"))  # 写回后重读一次，确认没写坏
```

`source` 是字符串数组，每个元素是一行（保留 `\n`）；也可以是整个字符串，但数组写法与 Jupyter 一致。

**硬性要求**：
- **只能追加**，不得修改、删除、重排已有 cell。
- **不得直接文本拼接** ipynb，必须走 JSON 解析与序列化（`ensure_ascii=False, indent=1`，写回后重读校验）。
- 追加前检查最后 3 个 markdown cell，**去掉日期行后**内容完全相同则跳过（去重），并在报告中注明「跳过（重复）」。
- 目标文件不存在时按上面的骨架创建，目录不存在时先建目录。

## 四、判断归属规则

1. 分析对话，提取知识点。
2. 先判断**科目**（408 / Math1 / English1 / Politics / Misc）。
3. 再按**概念主题**判断归属，不按课本章节。
4. 跨科目、跨主题内容 → 拆成多段，分别追加到不同文件。
5. 无法确定 → `Misc/临时问题.ipynb`，标题加 `[待归类]`。
6. **宁可 Misc，不要强行塞进不匹配的章节。**

**「建文件」与「进 Misc」的边界**（规则 7 的准确表述）：

- 主题在第二节覆盖表中有明确归属、只是文件还没建 → **按命名规范创建文件**，正常追加。
- 覆盖表里**根本没有**对应主题（全新方向） → **不要自创新文件**，写入 `Misc/临时问题.ipynb` 并加 `[待归类]`，是否开新文件由用户决定。

### 判断决策树

```
1. 对话里有没有明确说「当前在学 X 科目 / X 主题」？
   → 有：先按当前科目和主题归类。
2. 知识点是否属于当前主题？
   → 是：写入当前主题对应文件。

```
