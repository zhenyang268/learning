# math-to-code.md — 数学对象 → 代码形态的映射规则

> **定位**：只回答两个问题 —— **「这个数学对象该以什么形态进代码」** 与 **「它给我哪条可执行判据」**。
> **不写**：任务、顺序、期限、优先级 → 那些只进根 `NOW.md`。
>
> 相关：数学地图 → `docs/route-math.md`；判据规范 → `graphics/acceptance.md`；
> 容差与错误类型 → `graphics/numeric-contract.md`；踩坑 → `docs/pitfalls.md`。

---

## 0. 为什么不用「按数学对象分类」

按对象分类（可计算公式 / 恒等式 / 推导工具 / 算子 / 几何恒等式）**必然重叠**：
分部积分既像「恒等式」又像「推导工具」，散度定理既像「恒等式」又像「几何公式」。
原因很朴素：

> **数学对象与代码形态之间不是函数关系。** 同一个定理在流水线里有三处可能的落点，
> 取决于要它干什么。

拿分部积分在 1D 泊松里举例，它同时做三件事：

1. 把 `∫u''v` 变成 `∫u'v'` —— **生成弱形式**（写代码）；
2. 边界项 `[u'v]` 决定边界条件怎么进刚度矩阵（**装配**）；
3. 给出对称性判据 `K ≈ K^T`（**只做断言，不写代码**）。

所以分类轴换成 **「它在这条流水线的哪一层被消费」**，而不是「它是什么」。

---

## 1. 第一刀：先选离散化

**离散化策略决定哪些定理会进你的代码路径。** 同一个泊松方程，FDM 一次都不用分部积分，
FEM 必须用一次。所以顺序是：**先选离散化 → 再问这条定理要不要用**，
不是先给定理分类再找落点。

| 策略 | 要分部积分吗 | 要积分吗 | 几何适应性 | 最小实现成本 |
|---|---|---|---|---|
| **FDM** | 不要 | 不要 | 差（规则网格） | 最低：差商 + 组装 |
| **FEM** | **要一次**（推弱形式） | 1D 等距线性元**也不要**；2D / 高阶要 | 好 | 中 |
| **FVM** | 不要（用通量形式） | 要（面通量） | 中 | 中 |
| 谱方法 | 不要 | 要（变换） | 差 | 高 |
| Monte Carlo | 不要 | 采样代替 | 任意 | 低，但收敛 `O(N^-1/2)` |

**条件句（不是建议，是推论）**：
- 若约束是「不手推积分、不手推弱形式」⇒ FDM 是唯一不需要任何推导的路径。
- 若约束含「复杂几何 / 自然边界条件」⇒ 必须 FEM，此时弱形式那一次分部积分**绕不过**。
- 若约束含「局部守恒」⇒ FVM，且代价是要处理通量重构。

## 2. 用法四层（L1–L4）

同一个对象可以同时占多层，**允许一格多标**。

| 层 | 含义 | 代码里的形态 |
|---|---|---|
| **L1 生成** | 用来推出一个离散格式 | 差商、求积公式、弱形式 → 函数或组装逻辑 |
| **L2 装配** | 决定边界项、系数、通量 | `assemble_boundary_load()`、`compute_flux()`、环路求和 |
| **L3 判据** | 不产生代码，只产生断言 | 对称性 `K ≈ K^T`、守恒、恒等式两边相等 |
| **L4 叙述** | 只在讲解里出现 | 存在唯一性、收敛性定理 —— **不进代码** |

**使用规则**：一个对象若只有 L3 / L4 标签，就**不该出现在实现清单里** ——
它该出现在测试或讲稿里。这条比任何分类都硬。

---

## 3. L1 与 L2 的硬分界：有无截断误差

比「能不能写成函数」更可靠的判据：

| | 有截断误差 | 没有截断误差（恒等式） |
|---|---|---|
| 例 | 差商、Simpson、Gauss 求积 | 散度定理、格林公式、分部积分恒等式 |
| 误差量级 | `O(h^p)`，随网格减小 | `O(ε_mach)` ≈ 1e-14，不随 h 减小 |
| 判据形态 | **收敛阶**：h 减半误差降 2^p 倍 | **两边差**：必须落在舍入级别 |
| 陷阱 | 用一次加密的比值冒充阶数（至少要三次） | 拿恒等式去验 `O(h^2)` —— 量级对不上，永远过不了 |

这条判据的价值：**它直接告诉你验证方式该长什么样**，而不是分完类再想怎么验。

## 4. 映射表（每行强制带判据）

| 数学对象 | 代码形态 | 层 | 判据（条件 + 数字） |
|---|---|---|---|
| 一阶差商 | `(f[i+1]-f[i-1])/(2h)` | L1 | 与解析导数比，h 各减半三次，误差比 ≈ 4 |
| 二阶差商 | `(u[i+1]-2u[i]+u[i-1])/h^2` | L1 | 同上 `O(h^2)`；截断误差 `τ = h^2·u⁗/12` |
| **Gauss–Legendre 求积** | 节点 = `P_n` 的根；权重 `w_i = 2/((1-x_i^2)·[P_n'(x_i)]^2)` | L1（**含算法**） | 对 `x^k, k ≤ 2n-1` **精确**（误差 ≤ 1e-15）；`k = 2n` 立刻退化 |
| 分部积分 | 弱形式 `∫u'v' = ∫fv` | L1 + L2 | `K ≈ K^T`（≤ 1e-14）；与 FDM 解在 h→0 时同阶 |
| Galerkin / 变分 | 刚度 + 载荷组装 | L1 | 能量泛函随加密单调下降并收敛；残差 `‖Ku-f‖` 的阶 |
| 散度定理 | 面通量求和 `Σ F·n·A` | L2 | 内部 `Σ ∇·` vs 边界 `Σ F·n`，相对误差 ≤ 1e-12 |
| 格林公式 | 多边形面积 = 环路积分 | L2 | 与三角形分解法比，相对误差 ≤ 1e-14 |
| 泰勒展开 | 局部截断误差分析 | L1 + L3 | 只产出**阶数**；实现是差商本身，不是泰勒 |
| 稳定性 / CFL | 时间步长上界 | L3 | 超阈值误差爆炸；**给出实测阈值**（例 `Δt_max ≈ 1.2h^2`） |
| 守恒律 | — | L3 | 离散总质量/能量漂移 ≤ `C·h^p`，给实测 `p` |
| 泊松方程（椭圆） | 组装一次 → 解一次 | L1 | h 减半误差降 4 倍；与解析解逐点比 |
| 热 / 波动 / ODE | 时间循环 → 每步解一次 | L1 | 双收敛（h 与 Δt）；能量守恒或**有界漂移** |
| 特征值问题 | 幂迭代 / Lanczos / QR | L1 | 残差 `‖Av - λv‖` 的阶；正交性 `V^T V ≈ I` |

**读法**：L1 = 写代码；L2 = 装配时别写错；L3 = 测试里断言；L4 = 不进代码。

> 每条的"条件"里必须含 **规模 / 容差 / 基线**。没有条件的数字在评审时等于没数字
> （口径见 `graphics/acceptance.md` §1 与 `graphics/numeric-contract.md` §4）。

## 5. 三条结构性事实

### 5.1 三件事不该捆成一件

「1D 泊松 → 稀疏 CSR → CG」常被当成一条链路，实际是**三件互不依赖、验不同东西**的事：

| 件 | 何时需要 | 验什么 |
|---|---|---|
| **三对角 + Thomas**（`O(n)`，约 20 行） | 1D 问题，`n ≤ 数千` 稠密即可 | **离散格式的收敛阶**（h 减半、误差降 4 倍） |
| **稠密 CG**（约 30 行） | 想验迭代法的收敛行为 | **迭代收敛性**：残差单调、迭代数 `~√κ` |
| **CSR + SpMV** | `n ≥ 10^4`、或要做性能分析 | 访存与带宽（属性能工程，不是"跑通链路"） |

**关键区分**：Thomas 是直接法，验的是**格式精度**；CG 是迭代法，验的是**迭代行为**。
两者不是二选一，是各验一件事。把 CSR 捆进来会让"验收敛阶"这件事被"写稀疏格式"阻塞。

### 5.2 1D 等距线性元不需要 Gauss 积分

`K_ij = ∫ φ_i' φ_j'` 在等距线性元上是常数：`K = (1/h)·tridiag(-1, 2, -1)`。
**手推比写积分代码还快。** Gauss 积分是 2D、高次元、变系数才必需的。

⇒ FEM 的真实门槛只在「弱形式那一次分部积分」，**不在积分**。这个细节会显著改变成本估计。

### 5.3 Gauss–Legendre 的节点是算法，不是公式

节点不是查表能解决的常数，是 `P_n` 的根。两条实现路径：

- `n ≤ 3`：写死表（最快，够用）。
- `n` 大：**Golub–Welsch** —— 构造三对角 Jacobi 矩阵，节点 = 特征值、权重 = 首分量平方 × 2。
  可直接复用已有 `eigen`，不必手写 Newton 求根。

若把它当"T1 直接写函数"，会卡在「节点从哪来」这一步。

## 6. 可复用 prompt（给其它 agent）

> 环境部分**故意不写死"已有/没有"** —— 那是状态，会腐化。让 agent 自己核实。

```text
你是一个「数学 → 数值代码」的翻译器。任务不是把公式抄成函数，而是判断每个数学对象在代码流水线的哪一层被消费，并给出可执行判据。

【第一件事：核实环境，不要猜】
- 语言固定 C++20（concept + ScalarTraits），不是 C++17。
- 仓库是 graphics/。
- 动手前先读 dev-progress.md §0，并 ls graphics/src/ 与 src/math/，确认"已有/没有"。
  不要凭这段文字推断现状；不要假设存在任何未核实过的文件或目录。

【规则一：先选离散化，再谈定理】
给定一个 PDE/ODE，先说明选 FDM / FEM / FVM / MonteCarlo 中的哪个，并指出这个选择让哪些定理进入代码路径。
不要先给定理分类再找落点。

【规则二：每个对象标用法层，允许一格多标】
- L1 生成：推出离散格式（差商、求积、弱形式）→ 产出函数或组装逻辑。
- L2 装配：决定边界项/系数/通量 → 产出 assemble_* / compute_*。
- L3 判据：不产代码，只产断言（对称性、守恒、恒等式两边相等）。
- L4 叙述：只在讲解里出现（存在唯一性、收敛性定理）→ 明确说「不进代码」。

【规则三：用截断误差区分 L1 与 L2】
- 有截断误差 → 可写函数、可验收敛阶（h 至少减半三次，比值对 2^p）。
- 无截断误差（恒等式）→ 只能验「两边差在舍入级别」（~1e-14），不许当成 O(h^p)。
两类判据不许混用。

【对每个对象输出七项】
1. 用法层标签（L1/L2/L3/L4，可多标）+ 一句话理由。
2. 离散化依赖：在 FDM / FEM / FVM 里分别是什么形态；不适用写「不使用」。
3. 代码形态：最小 C++20 片段，只给核心 20–40 行，必须可编译（不是伪代码）。
4. 判据：写成「条件 + 数字」。条件含规模 / 容差 / 基线。例：n=100、容差 1e-10、h 减半三次、误差比 ≈ 4。
5. 失败模式：至少两条（边界项漏掉、积分点不足、条件数爆炸、收敛阶不对）。
6. 不推导的替代路径：优先 FDM 或「弱形式 + 数值积分」，说明代价（精度 / 几何适应性）。
7. 面试讲法：三句话 —— 为什么这么离散、误差多大、什么时候会坏。

【禁止】
- 不展开证明；推导只给「关键一步 + 结论」，例：分部积分把 ∫u''v 变成 ∫u'v'，边界项因 v=0 消失。
- 不给 PETSc/MKL/Eigen 的实现，只在「对标物」处提一句。
- 不写「误差很小」，必须是数字或阶数。
- 若对象是 L3/L4，明确写「不要写 xxx() 函数」并指出它真正的落点。

【第一个任务，逐个输出】
1. 二阶差商（1D 泊松的 FDM 离散）
2. Gauss–Legendre 求积（节点来源 + 1D/2D 张量积）
3. 分部积分（1D 泊松弱形式里的作用，以及边界项去哪了）
4. 散度定理（1D 有限体积通量 / 2D 格林公式求面积）
5. 三对角 Thomas 与稠密 CG（分别验什么，为什么不用 CSR）

最后一张表：FDM vs FEM 在「推导成本 / 代码复杂度 / 精度 / 几何适应性 / 面试可讲性」五维对比，
给一句结论：在「不手推 + 快速跑通」约束下哪个更合适。
```

## 7. 边界

- **不写顺序、期限、优先级** —— 只写映射规则与判据形态。做什么 → `NOW.md`。
- **不收录具体实现** —— 实现进 `graphics/src/`，判据进 ctest 用例；本文只给"该长什么样"。
- **不评价某种离散化"更好"** —— 只有"在给定约束下更合适"，且约束由用户给。
