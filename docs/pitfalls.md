## 一、判据病态 ≠ 实现错

**现象**：误差稳定在 `2e-8` / `3e-8` 这种"像 bug 又不是 bug"的数值上，反复调实现也压不下去。

**根因**：用 `acos((tr−1)/2)` 量旋转角，在 θ→0 和 θ→π 处导数发散（`d/dθ acos` 分母带 `√(1−x²)`），
有限精度下必然给出假误差。

**正解**：换等价良态式 —— `θ = atan2(‖vee(R−Rᵀ)‖/2, (tr−1)/2)`，回到机器精度。

**同族**：
- `slerp` 匀速性判据同理（用 `acos` 测夹角）。
- 条件数 `e^{2‖A‖}` 的 `exp(A)exp(−A) = I` 在大范数下**本身**就是病态的判据 ⇒ 换 `det(exp X) = exp(tr X)`。
- `expm` 的级数路线在 `‖A‖` 大时卡在 `≈(e^‖A‖/√(2π‖A‖))·eps` 地板 —— 这是**精度地板**，不是 bug。

## 二、对称/共轴会掩盖顺序与符号 bug

- **`R·p` 的常轴情形下左乘 ≡ 右乘**（两者都是 `Rpⁿ`）⇒ 验证复合顺序**必须喂非共轴 + 时变序列**。
  单轴自转测不出顺序 bug；曾以为"顺序写反误差差 6~9 个量级"，是拿常轴做的错误实验。
- **奇次恒等式抓不到整体翻号**：`Hat³ = −|u|²·Hat` 与 `Vee∘Hat = id` 两边都是奇次，
  `Hat` 整体翻号时互相抵消、恒等式仍成立。⇒ 符号必须靠「六个非对角位置逐位比对」+「`Cross` 对拍」钉。
  与 `quaternion.hpp:110`「叉积符号写反，往返测试抓不到」同一类盲区。
- 同理，**反对称张量完整存储但符号一致地错**时，对称性判据全绿。

## 三、holonomy 有两套口径，混用必错

- G3 转角用**极角 θ₀**（从北极量）写作 `−2π·cos θ₀`；若改用**地理纬度** φ = 90° − θ₀，
  则写作 `−2π·sin φ`。**「2π·cos(纬度)」是两种口径混用，错的。**
- G4 的 holonomy：用「首末向量夹角」口径得 `+π/2`；用「沿途切向标架连续展开」口径得 `−π`。
  **两者参照系不同，不 mod 2π 同余。** 三重验证用的是前者。

## 四、照"看起来对"的骨架写会写出跑不过的用例

两条已核实的错误表述（骨架正确、结论不成立）：

**① 「`X = S + A` ⟹ `exp(X) = R·P` 且 `R = exp(A)`、`P = exp(S)`」—— 一般不成立。**
`exp(S+A) ≠ exp(S)·exp(A)`，除非 `[S,A] = 0`；差的正是 BCH 首项那一阶 `½[S,A]`。
正确说法是**分开的两句**：`exp(对称)` 是正定对称阵、`exp(反对称)` 是旋转；
任意可逆阵有极分解 `G = R·P`，但 `G = exp(X)` 的因子一般不等于 `exp(A)`、`exp(S)`。

**② 「exp 是局部一一对应」不够，要补全局性。**

- `so(3) → SO(3)` 的 exp **满射但不单射**（θ 与 θ+2π 同像）；
- 一般李群上 exp **连满射都不是**（`SL(2,ℝ)` 有元素不在任何 `exp(X)` 的像里）。

## 五、泛型域（`Complex` / `Dual` / `ScalarTraits`）

- `real_t` 与 `T` 不能直接相乘 ⇒ `ScalarTraits<T>::fromReal(x) * y`。
- `Dual<Complex>` 字面量须写 `DC(C(0,0), C(0,0))`；`RandFill<Dual<Complex<U>>>` 需单列特化。
- `Matrix * T` 有成员重载，**无 `T * Matrix`**、**无 `operator/`**、只有 `+=`。
- 比较走 `Abs2`；`DefaultTol<T>(n) = 8n·eps`。
- `std::invalid_argument` / `std::out_of_range` **都派生自 `std::logic_error`**
  ⇒ "断言 throw `logic_error`"会**假绿**，必须精确到子类。

## 八、结构探测的「编得过但算得错」（2026-10-14 实测，两条）

这类 bug 最贵：**编译器不报、用例不报、但语义整体失效**。

**① `is_symmetric` 比较对象写错**

```cpp
// 错：AH(j,i) = conj(A(i,j))，于是比的是「A(i,j) 的虚部是否为 0」
if (Abs2(A(i,j) - AH(j,i)) > tol*tol) return false;
// 对：应比 AH(i,j)
```

**后果**：**实数矩阵恒真 ⇒ 所有实方阵都被判成 `Symmetric`**，`Classify` 语义整体失效，**静默无报错**。

**② `is_orthogonal` 只查对角线**

`A^T·A` 对角全 1、非对角非零的矩阵（如 `[[1,c],[0,√(1−c²)]]`）会被误判成正交。
**必须全元素检查**：对角比 `one()`、非对角比 `zero()`。

**③ 附带一条量纲坑**：统一写 `abs2 <= tol*tol`（平方量对平方阈值）。
写 `abs2 <= tol` 是把「模长阈值」当「模长平方阈值」用 ⇒ 实际容忍度变成 `√tol`，差一个数量级。

**抓这两条需要专门的判据**：`A = [[1,c],[0,√(1−c²)]]`（对角全 1、非对角 `c≠0`）。
只用随机矩阵抓不到 —— 随机阵的非对角本来就不为 0。

## 九、注入对照的两个隐藏陷阱（会复发，每次注入都要看）

**① 恢复文件后必须 `touch`**

`shutil.copy(BAK, SRC)` 之后，CMake 按 **mtime 粒度**可能判 "up-to-date" ⇒
**跑的还是注入版二进制**。表现是「明明恢复了，还是 FAIL」，极易误判为「恢复失败」。

**解法**：恢复后 `touch <源文件>` 或删构建产物，再跑。

**② 判「注入是否被抓」只看 FAIL 数的增量，别信单次跑**

单次结果受「上次是否真的重编译」影响。正确做法：
`跑基线（记 FAIL=0）→ 注入 → 跑（FAIL 应 >0）→ 恢复 + touch → 跑（应回 0）`。

## 十、`Dual` 的「局部导数」不看种子（2026-10-17）

`Derive(Apply(A, f))` 得到的是 **`f'(x)·A.derive`** —— **依赖外部种子**；种子为 0 时局部导数全为 0。

这正是「**反向模式里没有 `derive`**」的含义。要取与种子无关的局部导数，必须显式把每格
`derive` 设成 1（单位种子）再取：

```cpp
template <typename T>
Matrix<Dual<T>> LocalDeriv(const Matrix<Dual<T>>& A, FunctionType f) {
    Matrix<Dual<T>> A1 = A;                  // 拷贝，不改上游
    for (int i = 0; i < A1.Size(); i++) A1.Data()[i].derive = ScalarTraits<T>::one();
    return Derive(Apply(A1, f));
}
```

**"我本来以为 `Derive` 就是求导"** 是最常见的误解起点 —— 它给的是**方向导数**，
方向由种子决定；只有全纯/线性场合才与方向无关（见 `docs/math-log.md` 的双种子口径）。

## 十一、工具链的静默失败（本机专属，2026-10-14 / 10-28 两次踩）

- **`grep "a\|b"`（BRE 的 `\|`）在本环境静默零命中**，看着像「Edit 没落盘」。
  用 `grep -E "a|b"` 或 Grep 工具。
- **本环境实测更怪：`grep -n "pattern" <单个文件>` 也会偶发零命中**（同一 pattern 换 `rg` 立刻命中）。
  ⇒ **判"内容是否存在"不要只信一次 grep**，尤其是拿它做验收时（会得出反向结论）。
- **`grep '检查'` 会漏用例**：`scalar_traits` 与 `compute_graph` 用手写 `printf`（`got=/want=` 格式），
  不打印「检查 N 项」⇒ 统计判据数必须 `grep -c '\[OK\]'`。
