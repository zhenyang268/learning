## 0. 两把尺子的定义

### 0.1 一句话区分

| | **学习 60**（懂） | **工程 60**（能做） |
|---|---|---|
| **一句话** | 能讲清「它为什么存在」 | 能证明「它在我手里是对的」 |
| **判断动作** | 让人追问三层，你答得住 | 跑一遍，数字对得上，错的地方你知道 |
| **允许缺什么** | 代码、性能、边界 —— **可以零代码** | **一项都不许缺** |
| **典型误判** | 「我读过」当「我懂了」 | 「跑通了」当「做对了」 |
| **失败特征** | 说不出「上一个方法为什么不够」 | 数字没有条件（机器/规模/容差） |

### 0.2 学习 60 的判定方法（三级，取一级）

> 来源 `docs/route-math.md` §1，本文沿用并泛化到四条线。

对着任意一个概念，自问四句，**四句都能答 = 一级 = 合格**：

1. **它解决什么问题**（不给它，会卡在哪）
2. **之前的方法为什么不够**（不是"更早所以更差"，是具体在哪失效）
3. **每个符号是什么**（不能有一个"约定俗成"的变量）
4. **在已有实例里的对应物**（能指到一个具体例子，不是抽象描述）

- 二级 = 见符号认得（**不算 60**）
- 三级 = 只会套公式（**比二级更糟** —— 制造"我会了"的错觉）

### 0.3 工程 60 的判定方法（三件套，缺一不算完）

> 来源 `docs/eng-competency.md` §0.2。**这是 60 分与「我跑通了」的唯一分界。**

```
条件  +  数字  +  失败模式
```

- **条件**：机器、编译器与优化级、规模、容差、基线是什么
- **数字**：误差 / 收敛阶 / 迭代数 / 加速比 / 内存，**要能和基线对照**
- **失败模式**：什么输入会让它错、错成什么样、**你是怎么发现的**

反例：「CG 快 3.2x」→ 噪音（不知道是不是换了机器）。
正例：「N=10^5、float64、-O3、容差 1e-8，对比 Jacobi 预条件，迭代数 812 → 96，预条件耗时占比 7%」。

### 0.4 两者的桥：**能不能让数学被验证**

> `docs/route-math.md` §0：某件工程物该不该做的判据是「**能不能让数学被验证**」。

- 讲得清但落不了地 → 停在 50（知道，但没验证过）
- 落得了地但讲不清 → 也是 50（会做，但不知道为什么）
- **两者都到 → 60 分，且是稳的 60**

## 1. 数学线（Math）

### 1.1 学习 60 —— 逐段检查点

> 判据：`docs/route-math.md` §3 的十段「看懂线」。下面把每段**拆成 3 个必答问题**，
> **全答得出 = 该段学习 60**。允许跳证明，不允许跳定义。

| 段 | 必答三问（全答出才算过） | 常被漏掉的 |
|---|---|---|
| **0 测度与积分** | ①黎曼积分为什么不够（举出 Dirichlet 函数、滑动尖峰）②三大收敛定理**各封死哪条逃逸路线** ③外测度为什么需要 Carathéodory 限制才能成测度 | ②容易只背结论，说不出"哪个极限操作会失效" |
| **1 概率三件** | ①独立**为什么等于**乘积测度（不是"互不影响"这种口语）②条件期望**为什么是正交投影**（为什么不是"加权平均"）③卷积的三种身份**为什么是同一件事** | ②说不出投影的定义（内积为零） |
| **2 L² 与傅里叶** ★ | ①完备性为什么是**关键**（不完整就做不了投影）②傅里叶级数与傅里叶变换**为什么是同一条谱定理的两半** ③Parseval 为什么是勾股定理 | ②说不出"离散谱 vs 连续谱"的对应 |
| **3 泛函三失效** | ①紧性失效**为什么直接打死变分法第二步** ②有界 != 连续在无限维如何裂开（给反例）③谱为什么可能连续 | ①说不出"有界列提不出收敛子列"这句话跟变分的关系 |
| **4 Sobolev 与弱解** | ①「解」按定义**为什么就是弱解** ②嵌入定理在说什么（维数如何决定正则性）③Rellich–Kondrachov 的"紧"从哪来 | ①说不出"经典解不够"的具体反例 |
| **5 变分两出口** ★ | ①同一条 dS=0 **为什么对曲线给 ODE、对场给 PDE** ②**边界项为什么必须处理**（不处理会漏掉什么）③Noether 的完整因果链 | ②这是绝大多数人漏掉的一步 |
| **6 流形与张量场** | ①**张量 = 换坐标按规则变的场**（不是"多维数组"）②为什么 Gamma 不是张量而 R 是（变换律差在哪）③上下标位置**谁在承载类型** | ②说不出"非齐次项" |
| **7 联络与曲率** | ①曲率 = **绕小回路不闭合**（holonomy 口径）②Bianchi 恒等式**为什么蕴含守恒** ③Ricci 是 R 的哪种缩并 | ②说不出"守恒"是微分还是代数结论 |
| **8 场方程** | ①场方程 = **变分 + Bianchi** 两样缺一不可 ②为什么必须是 G_uv（二阶 + 守恒 + 无多余自由度）③Schwarzschild 怎么从真空解出来 | ①单独说"最小作用量"是不完整的 |
| **9 洛伦兹与因果** | ①号差改一个符号**为什么把椭圆型变双曲型** ②视界作为因果结构的边界（不是"光出不来"）③测地线完备性为什么是"真奇点"的判据 | ②容易停留在物理图像 |

**学习 60 的边界**：不看证明、不做技巧题、不背公式表。
**但必须能画出依赖图** —— 说清这一段依赖哪几段、被哪几段依赖。

| S-L3 | **进程与线程** | ①本质区别（**地址空间 vs 调度单位**）②上下文切换**切换了什么**（为什么它贵）③用户态/内核态切换为什么存在（保护 vs 性能） |
| S-L4 | **并发与同步** | ①**数据竞争的定义 = happens-before 被违反**（不是"两个线程同时写"）②为什么互斥锁需要**硬件原语**（CAS/xchg）③死锁四条件（Coffman）与各自破坏手段 ④内存序（acquire/release）在保证什么 |
| S-L5 | **网络** | ①分层为什么这样切（每层只依赖下层接口，不是"历史原因"）②TCP **为什么三次握手**（两次不够：旧连接请求）③拥塞控制 vs 流量控制（**网络 vs 接收方**）④为什么 TCP 有粘包问题 |
| S-L6 | **数据结构与算法** | ①每个结构的**不变量**是什么（红黑树五条 / 堆偏序 / B 树阶）②**均摊 vs 最坏 vs 期望**的区别（各举一例）③哈希冲突处理的取舍 |
| S-L7 | **编译与链接** | ①四阶段各做什么（预处理/编译/汇编/链接）②**为什么需要链接**（分离编译 + 符号解析）③静态 vs 动态链接的代价 |
| S-L8 | **分布式基础（若涉及）** | ①CAP 的准确表述（不是"三选二"）②为什么需要共识（不是"为了高可用"）③线性一致性的定义 |

### 4.3 CS 线专属的「学习 vs 工程」分界

这条线**最容易自我欺骗**，因为「读源码」感觉很像「懂了」。

| 活动 | 学习 60（够了） | 工程 60（还不够） |
|---|---|---|
| 读 xv6 / jos | 能讲清 `fork` 为什么返回两次、COW 的页表怎么翻 | **自己加过一个系统调用 / 修过一个 race** |
| 读 CS144 | 能讲清滑动窗口与 ACK 自时钟 | **自己实现的 sender 通过了全部测试** |
| 读 CSAPP | 能讲清 cache 映射与冲突 | **用实测证明过某个循环的瓶颈在哪** |

> **判据一句话**：
> **「我改过并跑通了」是工程 60；「我读懂并能讲清」是学习 60。二者缺一不可，但不能互相冒充。**

### 5.2 同一件东西在四条线上的「60 分」不同

**这是最容易混的地方** —— 一个 `ode.hpp` 在四条线上的判据完全不同：

| 线 | 对 `ode.hpp` 的 60 分要求 |
|---|---|
| **数学** | 能讲清"为什么 RK4 是四阶"（Taylor 展开匹配项数）；能说清离散化误差与截断误差的区别 |
| **数学物理** | 能量守恒曲线（辛 vs 非辛）；初值敏感性数字 |
| **CG** | 能用于相机/刚体运动积分，**结果看不出抖动**（稳定性够用） |
| **CS** | 代码能被人接手（接口清晰 + 单测 + 不泄漏）；**性能不是首要** |

> **⇒ 这就是为什么必须有四组判据，而不是一组。** 同一份代码，四条线各自的"60 分"答案不同。

### 5.3 并行资产：微基准仓（2026-10-28 实测）

`learning/learning-benchmark/`（独立 git 仓，**10 次提交**）是 **HPC 赛道的专用载体**，
**设计全部闭合、代码未开工**。两条实测结论直接改变上面判据的可行性：

| 结论 | 对 60 分判据的影响 |
|---|---|
| **硬件 PMU 不可用**（`unsupported p6 CPU model 183 no PMU driver`） | `eng-competency.md` §1.2 #3「用 profiling 定位瓶颈」**不能靠 perf 计数器** ⇒ 必须走**唯一变量对照实验**（改一处、看差异）。这**同样是 60 分能力**，且更难得（不依赖工具特权） |
| **不绑核**（WSL2 拓扑是合成的：`lscpu` 报 10 核 x 2 线程，与真实 6P+8E 不符） | §1.2 #4「并行基础」可写、可跑，但**多线程加速比不可引用**（`reliable=false`）⇒ **HPC 60 的「并行」只能算半个** |

> **#1 稀疏算子 / #2 迭代求解 / #3 性能分析（对照法）** 三条可以真做；
> **#4 并行** 只能到「能写能跑、但不给加速比」——**面试时必须主动说明这个限制**，
> 这比给一个不可引用的数字更可信。

## 6. 怎么用这张表（自查方法）

**不要一次全测。** 按下面三步：

1. **选一条线 + 一把尺子**（例如「数学 + 工程」）。
2. **逐条打勾**：能做到写「✅ + 证据编号」；做不到写「❌ + 缺什么」。
3. **只处理 ❌ 里最靠前的那一条** —— 不要并行修五个缺口（会全部半途）。

**判定门槛（本仓口径）**：

| 打勾率 | 结论 |
|---|---|
| 学习 60 全 ✅、工程 60 < 50% | **会说不会做** —— 补工程，别再看书 |
| 工程 60 全 ✅、学习 60 < 50% | **会做不会讲** —— 面试会挂，补"为什么" |
| 两者都 > 80% | 已达 60 分，**开始看 80 分**（`eng-competency.md` §4 的五条通用差距） |

## 7. 一句话

> **学习 60 = 能讲清「它为什么存在」；工程 60 = 能证明「它在我手里是对的」。**
> **前者可以零代码，后者一项都不能少（条件 + 数字 + 失败模式）。**
> **四条线各有一套，因为同一份代码在四条线上的"60 分"答案不同**（§5.2）。
> **两者的桥是「能不能让数学被验证」** —— 讲得清但落不了地，停在 50；落得了地但讲不清，也是 50。
