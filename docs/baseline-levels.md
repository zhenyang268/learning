## 0. 标尺本身

### 0.1 两把尺子

| | **学习**（懂） | **工程**（能做） |
|---|---|---|
| **一句话** | 能讲清「它为什么存在」 | 能证明「它在我手里是对的」 |
| **判断动作** | 让人追问三层，你答得住 | 跑一遍，数字对得上，错的地方你知道 |
| **允许缺什么** | 代码、性能、边界 —— **可以零代码** | **一项都不许缺** |
| **典型误判** | 「我读过」当「我懂了」 | 「跑通了」当「做对了」 |
| **失败特征** | 说不出「上一个方法为什么不够」 | 数字没有条件（机器/规模/容差） |

### 0.2 三档的定义（**通用骨架，四线共用**）

| 档 | 一句话 | 学习侧判据 | 工程侧判据 |
|---|---|---|---|
| **60** | **能上车** | 能讲清定义、动机、在已知实例里指得出对应物 | 独立实现经典方法；能**定量**验证正确性/误差/收敛；能解释选型与**常见失败模式**；代码能被人接手 |
| **80** | **能独立负责一个模块** | 能讲清**边界**（什么时候失效）、**与替代方案的取舍**、**为什么是这个设计而非那个** | 覆盖**退化边界**；性能**可调优并有数字**；能定位**根因**（不是试出来）；有**规模化痕迹**；能写设计文档 |
| **90** | **能定义问题** | 能指出**这套理论自身的缺口**，并说清别人怎么绕开 | 定义新方法 / 工业级鲁棒 / 跨领域迁移；**别人按你的方案走** |

> **一句话记法**：
> **60 = 会用；80 = 知道它什么时候不灵，并能修；90 = 别人用你的。**

### 0.3 学习侧的判定方法（三级 + 80/90 加问）

> 来源 `docs/route-math.md` §1，泛化到四条线。

**60 档**：对任意概念自问四句，**四句都答 = 一级 = 合格**：

1. **它解决什么问题**（不给它，会卡在哪）
2. **之前的方法为什么不够**（不是"更早所以更差"，是具体在哪失效）
3. **每个符号是什么**（不能有一个"约定俗成"的变量）
4. **在已有实例里的对应物**（能指到一个具体例子，不是抽象描述）

- 二级 = 见符号认得（**不算 60**）
- 三级 = 只会套公式（**比二级更糟** —— 制造"我会了"的错觉）

**80 档加第 5 问**：

5. **它的边界在哪**（什么条件下失效；举一个失效的具体例子）

**90 档再加两问**：

6. **这套框架有什么它自己解决不了的问题**（不是"还没学完"，是理论缺口）
7. **主流是怎么绕开这个缺口的**（说出至少一条别的路线及其代价）

### 0.4 工程侧的判定方法（三件套，缺一不算完）

> 来源 `docs/eng-competency.md` §0.2。**这是 60 分与「我跑通了」的唯一分界。**

```
条件  +  数字  +  失败模式
```

- **条件**：机器、编译器与优化级、规模、容差、基线是什么
- **数字**：误差 / 收敛阶 / 迭代数 / 加速比 / 内存，**要能和基线对照**
- **失败模式**：什么输入会让它错、错成什么样、**你是怎么发现的**

反例：「CG 快 3.2x」→ 噪音。
正例：「N=10^5、float64、-O3、容差 1e-8，对比 Jacobi 预条件，迭代数 812 → 96，预条件耗时占比 7%」。

**80 档加两条**：

- **归因**：瓶颈在哪（带宽/算力/缓存/同步）—— **是测出来的，不是猜的**
- **规模化**：规模上去后暴露了什么、怎么解决的

### 0.5 覆盖率门槛（**回答「算不算过」**）

> 上一版没定义，导致「要么永远达不到、要么全都算过」。

| 判定 | 门槛 |
|---|---|
| **单条「过」** | 该条**全部必答项**都答得出（少一项就是不过，不许打折扣） |
| **整线「60 过」** | **核心项 100% + 其余 ≥ 80%**（各节标 ★ 的即核心项） |
| **整线「80 过」** | 60 全过 **且** 80 条目 **≥ 60%** |
| **整线「90」** | 80 全过 **且** 有**外部承认**（论文/开源被用/工业场景验证） |

**★ 核心项**的定义：**缺了它，这条线就不能说"入门"**。每条线各 3–4 个。

### 0.6 **反例判据（出现即否决，优先级最高）**

> 正向判据容易自我美化，**反向判据更难自欺**。**任一条命中 ⇒ 该档直接判不过。**

**工程侧一票否决（通用）**

| # | 反例 | 为什么否决 |
|---|---|---|
| N1 | 数字没有条件（说不出机器/规模/容差） | 无法复现，等于没有 |
| N2 | 只有一个实现，没有基线对照 | 「快」是相对谁？ |
| N3 | 只测了正常输入，没有病态输入 | 不知道边界，就是不知道 |
| N4 | 失败时静默返回错误结果（不是 throw / 不是报错） | 最危险的 bug |
| N5 | 代码只有自己能跑（硬编码路径 / 无构建脚本 / 无单测） | 不能被人接手 != 工程 |

**学习侧一票否决（通用）**

| # | 反例 | 为什么否决 |
|---|---|---|
| N6 | 能把公式写出来，但说不出**为什么是这个形式** | 那是抄，不是懂 |
| N7 | 说不出**上一个方法错在哪** | 说明只是记了结论 |
| N8 | 讲的时候用「显然」「大家都知道」跳过关键步骤 | 通常那里正是没懂的地方 |
| N9 | 只能复述教材顺序，换个提问角度就答不出 | 没有内化成结构 |

### 0.7 **验证机制（防止自评失真）**

> **这是本文最重要的补充。** 学习侧尤其容易失真 —— **因为没有人会来纠正你**。

| 档 | 谁来判断 | 具体做法 |
|---|---|---|
| **60** | **自评 + 一个外部检查点** | 学习侧：**讲给一个不懂的人听**（他 10 分钟能不能抓住主干）；工程侧：**跑一遍，数字对得上** |
| **80** | **同行 / 面试官级** | 学习侧：答得住**追问三层**（§0.8）；工程侧：**别人照你的 README 能复现你的数字** |
| **90** | **外部承认** | 论文被引 / 开源被用 / 他人按你的方案落地 |

**最低成本的外部检查点**（可立刻做）：

- **写**：把某个检查点写成 500 字短文，**不查资料**。写不下去的地方就是没懂。
- **讲**：找人讲 10 分钟，看他能复述出几句。
- **跑**：把数字重新跑一次，**换一天**。对不上说明条件没记全。

### 0.8 追问三层模板（判 80 档用）

任何 80 档结论都要答住三层：

1. **是什么**：你做了什么？—— *60 档要求*
2. **为什么**：为什么这样做而不是那样？取舍是什么？—— *80 档要求*
3. **什么时候不灵**：什么条件下会失效？你怎么知道的？—— *80 档的核心*

**答不住第三层 ⇒ 停在 60。**

## 1. 数学线（Math）

### 1.1 学习侧

#### 60 —— 逐段必答（★ = 核心项）

> 判据：`docs/route-math.md` §3 十段「看懂线」拆成三问，**全答出 = 该段过**。
> 允许跳证明，不允许跳定义。

| 段 | 必答三问 | 常被漏掉的 |
|---|---|---|
| **0 测度与积分** | ①黎曼积分为什么不够（举 Dirichlet 函数、滑动尖峰）②三大收敛定理**各封死哪条逃逸路线** ③外测度为什么需要 Carathéodory 限制 | ②只背结论，说不出"哪个极限操作会失效" |
| **1 概率三件** | ①独立**为什么等于**乘积测度 ②条件期望**为什么是正交投影** ③卷积的三种身份**为什么是同一件事** | ②说不出投影的定义（内积为零） |
| **2 L² 与傅里叶** ★ | ①完备性为什么是**关键** ②傅里叶级数与变换**为什么是同一条谱定理的两半** ③Parseval 为什么是勾股定理 | ②说不出"离散谱 vs 连续谱"的对应 |
| **3 泛函三失效** ★ | ①紧性失效**为什么直接打死变分法第二步** ②有界 != 连续在无限维如何裂开（给反例）③谱为什么可能连续 | ①说不出这句话跟变分的关系 |
| **4 Sobolev 与弱解** | ①「解」按定义**为什么就是弱解** ②嵌入定理在说什么 ③Rellich–Kondrachov 的"紧"从哪来 | ①说不出"经典解不够"的反例 |
| **5 变分两出口** ★ | ①同一条 dS=0 **为什么对曲线给 ODE、对场给 PDE** ②**边界项为什么必须处理** ③Noether 的完整因果链 | ②绝大多数人漏掉的一步 |
| **6 流形与张量场** ★ | ①**张量 = 换坐标按规则变的场** ②为什么 Gamma 不是张量而 R 是 ③上下标位置**谁在承载类型** | ②说不出"非齐次项" |
| **7 联络与曲率** | ①曲率 = **绕小回路不闭合** ②Bianchi **为什么蕴含守恒** ③Ricci 是 R 的哪种缩并 | ②说不出"守恒"是微分还是代数结论 |
| **8 场方程** | ①场方程 = **变分 + Bianchi** 缺一不可 ②为什么必须是 G_uv ③Schwarzschild 怎么从真空解出来 | ①只说"最小作用量"不完整 |
| **9 洛伦兹与因果** | ①号差改符号**为什么把椭圆型变双曲型** ②视界作为因果结构的边界 ③测地线完备性为什么是"真奇点"判据 | ②容易停留在物理图像 |

**核心项（缺一不算入门）**：段 **2 / 3 / 5 / 6** —— 这四段是「能读场方程」的最低配置。

#### 80 —— 逐段加问（第 5/6/7 问）

| 段 | 80 档加问 |
|---|---|
| 0 | ①哪条收敛定理在实践中**最常被误用**？举一个"以为满足条件其实不满足"的例子 ②Carathéodory 判据的**替代路线**（Daniell / 单调类）代价是什么 |
| 1 | ①条件期望在**非 L²**（只有 L¹）时怎么定义 ②卷积在**非交换群**上怎么变 |
| 2 | ①不完备的空间**具体坏在哪**（给一个 Cauchy 列不收敛的例子）②谱定理在**无界算子**下要多付什么条件 |
| 3 | ①三失效各自的**标准救法**分别付出了什么代价 ②为什么 Sobolev 嵌入有**临界指数**，越过它发生什么 |
| 4 | ①弱解**不唯一**的情形（举例）+ 需要什么额外条件 ②正则性提升的**天花板**在哪 |
| 5 | ①**自然边界条件** vs **本质边界条件**，从变分怎么区分 ②Noether **逆定理**成立条件 |
| 6 | ①**挠率**为什么在黎曼几何里消失、在 Einstein–Cartan 里不消失 ②张量密度与张量的区别 |
| 7 | ①Bianchi 的**两种形式**（代数 / 微分）分别蕴含什么 ②曲率分解（Weyl / Ricci / 标量）的物理含义 |
| 8 | ①**GHY 边界项**不加会怎样（具体坏在哪）②为什么场方程**不能高于二阶**（Ostrogradsky） |
| 9 | ①**能量条件**与奇点定理的逻辑链 ②因果结构如何决定**初值问题的适定性** |

#### 90 —— 判据

- 能指出**这套体系自身的缺口**（如：GR 与 QFT 的不相容具体落在哪个数学结构上）
- 能说清**至少两条不同的数学化路线**及其代价（层论 vs 传统微分几何；分布 vs Colombeau 代数）
- **不需要**：自己提出新理论

### 1.2 工程侧

#### 60 —— 逐条（★ 核心）

| # | 检查点 | 合格线 | 现状 |
|---|---|---|---|
| **M-E1** ★ | **失败语义显式** | 奇异/非方阵/非收敛 **throw 或返回明确标志**，**无静默算错**；阈值（如 `8n*eps`）**给依据** | ✅ |
| **M-E2** ★ | **判据独立于实现** | 至少一条**不依赖该算法自身**的不变量（`sum(sigma^2)=||A||_F^2`、`det(exp X)=exp(tr X)`） | ✅ |
| **M-E3** ★ | **病态输入必测** | 含 `n=0/1`、近奇异、尺度悬殊、零阵；**每类给实测误差与判据** | ✅ |
| M-E4 | **精度边界说得出数** | 给算法精度上限**与成因**（`A^H A` 路线 ⇒ `sqrt(eps)`），不是"大约 1e-15" | ◐ 有文档未成表 |
| M-E5 | **迭代类有收敛曲线** | 迭代法给**迭代数 vs 收敛率**曲线，斜率对得上理论 | ◐ 部分 |
| M-E6 | **算法有一个换法对照** | 同一问题两种算法，**给交叉点** | ✅ `expm` Taylor vs Pade |

> **⚠️ 相对上一版的一处修正**：删掉了原 `M-E1「线代全套各写独立实现」`。
> **理由**：面试官不问「你写过 SVD 吗」，只问「你知不知道什么时候不能用它」。
> **「自己实现一遍」是达成理解的手段，不是判据本身** —— 写进判据会把「实现工作量」
> 混进「数学能力」，导致为了打勾去重写已有代码（纯浪费）。
> **替代项**：`M-E4`（精度边界说得出**成因**）才是真正测"懂不懂"的那条。

#### 80 —— 逐条

| # | 检查点 | 合格线 |
|---|---|---|
| M-E7 | **数值稳定性有归因** | 能定位一次**实际发生的**精度损失到具体步骤（不是"浮点误差"），给出修法与其代价 |
| M-E8 | **误差有阶的拟合** | 误差随规模/步长的**增长阶拟合成斜率**，与理论一致或能解释差异 |

- 实现的方法**被别人的项目采用**
- 或：能对**一个公认难题**（如大规模病态系统）给出**可验证的改进**

## 6. 自查方法

### 6.1 三步

1. **选一条线 + 一把尺子 + 一档**（如「数学 + 工程 + 60」）。
2. **逐条打勾**：过 = 「✅ + 证据编号」；不过 = 「❌ + 缺什么」。
3. **只处理最靠前的那个 ❌** —— 不要并行修五个（会全部半途）。

### 6.2 判定门槛

| 打勾情况 | 结论 |
|---|---|
| 学习 60 全过、工程 60 < 50% | **会说不会做** —— 补工程，别再看书 |
| 工程 60 全过、学习 60 < 50% | **会做不会讲** —— 面试会挂，补"为什么" |
| **命中任一反例（§0.6）** | **该档直接不过**，先修这一条 |
| 核心项有缺 | **整线不过**（核心项不可打折） |
| 两者都过 60 且核心项齐 | **进 80**：开始要求「边界 + 归因 + 规模化」 |

### 6.3 每三个月做一次「降档重测」

> **防的是"其实已经忘了但以为自己还会"。**

挑一个**已打勾过的 60 档项**，重新做一遍（重讲 / 重跑）。**做不出来就降档** ——
这不可耻，那是真实状态。
