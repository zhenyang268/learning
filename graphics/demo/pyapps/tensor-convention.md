## 0. 为什么先写约定而不是先写代码

张量的坑**不在公式，在记号**。同一个 `R^i_{jkl}`，数组下标顺序写成 `[i][j][k][l]` 还是
`[k][l][i][j]`、反对称的两轴是哪两轴、上下标是数值还是语义 —— 这三件事错了，
代码照样跑、数字照样出，**只有换坐标时才会暴露**。

所以约定必须在写第一个公式之前钉死。这与 `sphere/_core.py` 头部那段
「坐标约定（全目录统一，改动会连锁影响所有脚本）」是同一件事，只是提前到还没有脚本的时候。

**第一个物理 demo 出现时**：建 `pyapps/<主题>/_core.py`，头部 docstring **照抄本文 §1–§7**
（同 `sphere/_core.py` 款），并在末尾注明「本文件约定源自 `tensor-convention.md`」。

---

## 1. 指标与轴顺序

**（a）数组下标顺序 = 指标书写顺序**，不做任何"优化过的"重排：

```
R^i_{jkl}        ->  R[i][j][k][l]      (与 sphere/_core.py 同款)
Gamma^k_{ij}     ->  Gamma[k][i][j]
F_{mu nu}        ->  F[mu][nu]
C^{ij}_{kl}      ->  C[i][j][k][l]
```

**（b）上下标必须进变量名。** numpy 数组只有轴、没有上下标信息，一旦写 `V[i]` 就永久丢失了
"这是向量还是余向量"。约定：

| 记号 | 变量写法 | 含义 |
|---|---|---|
| `V^i` | `V_up[i]` | 逆变 / 切向量 |
| `V_i` | `V_down[i]` | 协变 / 余向量、梯度 |
| `A_{ij}` | `A_down_down[i][j]` | (0,2) 型 |
| `A^{ij}` | `A_up_up[i][j]` | (2,0) 型 |
| `A^i_j` | `A_up_down[i][j]` | (1,1) 型 |

啰嗦但值得 —— **这是本文唯一一条靠命名而非靠测试来保证的规则**，
因为 §6 第 3 类测试（坐标变换不变性）只在已经出错之后才报警。

**（c）爱因斯坦求和**：重复且**一上一下**的指标求和。两个上标重复（`T^i U^i`）不是合法的
求和式，是记号错误 —— 这一条靠人眼，不靠类型系统（见 §8）。

---

## 2. 缩并：一律走 `np.einsum` 字符串

```python
C = np.einsum('ijk,j->ik', T, V)     # 缩掉 T 的第 2 轴与 V 的唯一轴
s = np.einsum('ij,ij->',   A, B)     # 全缩并 -> 标量
```

**spec 字符串就是文档** —— 它同时说清了「哪些指标求和、哪些保留、按什么顺序输出」。
这是本文所有规则里性价比最高的一条。

### 允许的两类封装

```python
def lower(g, v_up):    return np.einsum('ij,j->i', g, v_up)
def raise_(g_inv, v_down): return np.einsum('ij,j->i', g_inv, v_down)
def norm_sq(g, v_up):  return np.einsum('ij,i,j->', g, v_up, v_up)
```

### 不允许的一类

```python
def contract(T, V, axes_T, axes_V): ...     # 别写
```

**判据：封装是否携带语义。** `lower` 携带（g 在前 = 降指标，一眼可读）；
`contract` 不携带（它就是 einsum 换个写法），还把 `'ijk,j->ik'` 这个最重要的信息
藏进了参数列表里 —— 等于把文档删掉换成两个整数。

### 手写 for 循环：**允许，且鼓励写一遍**

第一次学某个缩并时，先把多重 for 写出来跑一遍，和 einsum 版本**对拍**。
这不是重复劳动，是「你真的知道自己在缩哪两个轴」的唯一证据。
手算/手写版留在脚本里当注释或单独函数，`main()` 里打印两者的差。

## 3. 对称性：**只作判据，不作存储约定**

**约定：一律完整存储。** 反对称张量就是 `F[mu][nu]`，读就是 `F[mu][nu]`，
不提供 `get_F(mu, nu)` 之类的读取函数。

不采用「半存 + 读取函数」的理由（两条，都是本项目付过学费的同类坑）：

1. **省不下东西。** 4 维反对称半存省 8 个数；n 维省 n^2/2。pyapps 的规模是
   2×2 / 3×3 / 4×4，这点内存不值一个符号错误的风险。
2. **符号一致地错时，测试全绿。** 如果所有读取都走 `get_F`，那么 `get_F` 内部
   把号写反，任何只用 `get_F` 的判据都抓不到 —— 因为错误是**一致的**。
   实测同例（2026-10-20，`src/linalg/so3.hpp`）：把 `Hat` 整体翻号，
   `Hat³ = −|u|²·Hat` **仍然全绿**，因为两边都是奇次、翻号互相抵消。
   `quaternion.hpp:110` 那条「叉积符号写反，往返测试抓不到」也是同一类盲区。

同源规矩：`matrix.md` §3.7「不给稠密 `Matrix` 存运行期结构标签」——
数据一旦带隐含约定（我是对称/反对称/半存），而读取路径不统一，就会静默出错。

**反对称的正确位置是判据**（见 §5），不是存储策略。

> 半存的唯一正当理由：n 很大且内存真的不够。那时它也不该待在 pyapps，
> 该进库走稀疏结构 —— 那是另一份设计，不在本文范围内。

## 4. 升降：**按场景开关**（不是二选一）

升降规则写不写，取决于脚本在哪个场景。**每个脚本头部必须声明场景**（见 §7）。

| 场景 | 度规 | 升降函数 | 说明 |
|---|---|---|---|
| **E** 欧氏直角坐标 | `g = delta` | **不写** | 上下标数值相同，只保留语义。写 `lower()` 是空转自欺。 |
| **G** 非欧 / 弯曲坐标 | `g_ij(x)` 非平凡 | **必须写** | 球面 `g_ij` 是现成实例（fan-plan G5，K 三路对拍）。 |
| **R** 相对论 | Minkowski | **必须写** | 度规**不定**，先钉符号约定再写任何公式。 |

**场景 G/R 的额外三条**：

1. `g` 与 `g_inv` 都显式给出，并互相验证 `g @ g_inv ≈ I`（相对误差 ≤ 1e-12）。
   不要用到 `g_inv` 时才临时 `np.linalg.inv(g)` —— 那会把求逆的数值误差和
   张量公式的错误混在一起，出错时无法定位。
2. **场景 R 必须先钉号差**：`(-,+,+,+)` 还是 `(+,-,-,-)`。
   选错会让所有类时间隔、能动量、能动张量**整体差一个负号**，且数值自洽。
   写在脚本头部第一行，不要"默认大家都用同一个"。
3. 场景 E 里也不要为了"以后方便"预先写 `lower()` —— 空转函数比没有函数更危险，
   它会让人以为升降真的生效了。

## 5. 检查函数（三类）

```python
# ① 形状断言
assert T.ndim == 3                      # 轴数对不对
assert T.shape[1] == T.shape[2]         # 同维指标（若 j,k 同维）

# ② 对称性断言（结构性，不受舍入影响时用 == ；否则用 allclose）
assert np.allclose(F, -F.swapaxes(0, 1))          # 两阶反对称
assert np.allclose(G,  G.swapaxes(0, 1))          # 两阶对称

# ③ 自由指标平衡：靠「缩并结果 shape 符合 einsum spec」间接验
```

两条注意：

- **`swapaxes` 要指明是哪两轴**，别用 `.T`（对 ≥3 阶张量 `.T` 是**全轴反转**，不是转置前两轴）。
  这条本身就是最容易犯的错。
- **不要用 `assert` 做验收。** `python -O` 会把它整个关掉，且失败时只有一行、没有实测值。
  pyapps 现成口径是**末尾打印验收数字 + PASS/FAIL**：

  ```python
  worst = np.max(np.abs(F + F.swapaxes(0, 1)))
  print(f"验收：反对称残差 = {worst:.3e}  [{'PASS' if worst < 1e-12 else 'FAIL'}]")
  ```
  （样板见 `rotation/rodrigues.py` 的 `main()`。）
  `assert` 只留作**开发期**的形状/前置条件检查，不承担验收。

**自由指标平衡**：人工检查（看 spec 字符串两边是否同名同位置）。不上类型系统，见 §8。

## 6. 测试策略

三类必做：

1. **小规模手算对比** —— 2×2 / 3×3 手算 vs 代码。
2. **对称性测试** —— 反对称张量交换指标变号（§5 ②）。
3. **坐标变换不变性** —— `V' = R·V`、`A' = R·A·R^T`，检查物理量（标量）不变。

**第 3 类是唯一能抓住「上下标搞反」的判据**，务必写：

- 手算只验证你**算对了**你以为的那个公式；
- 对称性只验证**结构**；
- 只有变换律能验证你把 `A` 当成 (0,2) 型还是 (2,0) 型 —— 弄反了的话
  正确变换是 `A' = R^{-T}·A·R^{-1}`，数值立刻不对。

### 本项目口味的两条补充

4. **两条独立路径对拍**（3.3 第 2 条：判据独立于实现路径）。
   现成模板 = fan-plan G5 的「K 三路对拍」：`R_{ijkl}/det g`、里奇标量/2、sympy。
5. **病态输入必列**（3.3 第 4 条）。用例集必须含：退化/零张量、尺度悬殊的分量、
   坐标奇点处（球面的 theta = 0/pi）。好输入全绿不算通过。

## 7. 场景声明（简化边界）

**每个脚本头部 docstring 第一行必须写**，一字不改地套下面三句之一：

```
本脚本：场景 E，g = delta，上下标数值相同但语义保留。
本脚本：场景 G，g = g_ij(x) 非平凡，升降函数已启用。
本脚本：场景 R，Minkowski 度规，符号约定 (-,+,+,+)，升降函数已启用。
```

超出本文件的范围（弯曲时空、挠率、旋量、连续介质本构细节）**需另开场景约定**，
不在本文内临时加规则 —— 加规则要回到本文改，并同步所有 `_core.py` 头部。

## 8. 明确不做（防范围蠕变）

- **不进 C++ 库**。红线 #4 + `matrix.md` §6：高维靠展平/切片归约为二维线性代数，
  不造 `Tensor<T,rank>`。本文所有规则**只对 pyapps 的 Python 脚本有效**。
- **不造 Tensor 类**，也不造 Vector3。numpy 裸数组 + `np.einsum` 就是全部载体
  （`matrix.md` §6「存储层免费、运算层值钱」）。
- **不做 `ascontiguousarray` 优化**。当前规模（2×2~4×4）收益不成立，
  提前优化会把代码搞脏。等真有 10⁶ 点的场再说 —— 那时瓶颈也不是内存连续性，
  而是「能不能把整个问题归约成矩阵乘法」（见 `MEMORY.md` §四最小二乘那条）。
- **不上类型系统检查自由指标**。人工看 spec 字符串即可（§5 ③）。
