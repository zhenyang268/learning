## 0. 一句话：三层，各防一类事故

这个仓历史上出过的事故决定了这三层的划分。**每一层都是被一次真实事故逼出来的**：

| 层 | 目录 | 防的是什么事故 | 判不判对错 |
|---|---|---|---|
| **第 1 层** | `linalg/smoke.cpp` | **「文件在」冒充「能编译」** | **不判数值**（只判能不能被编译器吃下去） |
| **第 2 层** | `core/ autodiff/ linalg/ quat/` 的其余 `.cpp` | 「跑得通」冒充「算得对」 | **判**，有阈值 |
| **第 3 层** | `apps/`、`pyapps/` | 「有数字」冒充「现象对」 | **不判**，只看现象 |

**读这个目录的正确顺序**：先看 §1 的三层，再看 §2 的表找到你关心的用例，
最后按 §4 的规矩加东西。

## 1. 第 1 层：`smoke.cpp` —— 保护「编译」

### 1.1 它防的事故

2026-10-14 一次体检发现：**`linalg/` 528 行代码从未被任何编译单元 include 过**。
文件在、看着完整、文档写着「已落地」—— **但编译器从没看过它**。
模板代码的 bug 只在**实例化**时暴露，只 `#include` 抓不到。

**所以「已落地」的判定必须是「被某个 TU 实例化过」，而不是「文件存在」。**

### 1.2 它怎么保护

两段，**作用完全不同，不要合并**：

| 段 | 做法 | 保护什么 |
|---|---|---|
| **`[A]` 实例化闸门** | 对每个公开入口**取函数指针**（`&Fn<T>` ⇒ odr-use ⇒ 强制实例化），**刻意不调用** | 「每个入口都在 `double` 与 `Complex` 下各被实例化一次」。**独立于数值对不对** |
| **`[B]` 最小数值闸门** | 每个入口真跑一次，阈值 `1e-10` | 「跑得通 + 方向对」。**刻意比专项用例松** |

**为什么 `[A]` 要刻意不调用**：让「实例化」这件事和「数值正确」解耦。
如果只在 `[B]` 里调用，那么一个入口只要在 `[B]` 里没被用到，就等于没被实例化。

**三处登记，漏一处闸门静默失效**：`EntryTable` 一行 + `GateCount()` 一行 + `kEntryCount` 计数。
**这条规矩已被违反两次**，详见 `../test-map.md` §4.1（`expm_pade`、整个 `so3.hpp`）。

### 1.3 它保护不了什么

- **不覆盖 `quat/`**：四元数不在 `linalg`/`core` 的实例化范围内（`D16` 封死），
  由 `quat/quaternion.cpp` 自己保证。
- **不覆盖 `autodiff/`**：由 `scalar_traits` / `compute_graph` / `dual_complex` 覆盖。
- **不判算法精度**：`[B]` 的 `1e-10` 只证明「没写反」，不证明「精度够」。

## 2. 第 2 层：ctest 用例 —— 验证「算法对不对」

**17 个用例、1175 项判据、全绿。**
下表**只写「它坏了什么会悄悄出错」**，不写它怎么实现的。

### 2.1 `core/`（2 个）

| 用例 | 保护了什么 |
|---|---|
| **`scalar_traits`** | **整个库的地基**：同一份 `linalg` 源码能同时支持 `double` / `complex` / `Dual`。它坏了，报错会出现在模板深处（几百行之外），**极难定位**。含 `CommutativeScalar` 的 `a*b==b*a` 单测（这是「算法层零实复分支」的前提） |
| **`tensor`** | **哑容器契约不被破坏**。24 项全是「断言它仍然 `throw`」的占位 —— 实现一条就变红，红是提醒换真判据。**它保护的是「不许偷偷实现运算」** |

### 2.2 `autodiff/`（4 个）

| 用例 | 保护了什么 |
|---|---|
| **`compute_graph`** | **前向建图与求值的正确性**。图建错了，反向的梯度会「看起来能算」但全错 |
| **`apply`** | **`Apply` 的形状契约**（`D19` 分子布局）。历史上这里写错过：形状检查退化成恒真，导致**越界读**。它保护的是「形状不匹配必须报错，不许静默算」 |
| **`backward`** | **反向传播的伴随公式**。含最小闭环的**三方对拍**（解析 / 数值 / 图）—— 单靠一方都可能一起错 |
| **`jacobian`** | **雅可比是 m×n 分子布局、一次 sweep 填第 j 列**。布局翻案（`D19` 第二次修订）后，这是唯一的回归网 |

### 2.3 `linalg/`（9 个）

| 用例 | 保护了什么 |
|---|---|
| **`solve`** | **所有下游残差的分母**。`V1.2`–`V1.5` 的每个数字都出自 `LU + Solve` ——**它错了，后面每一步的残差都不值得信**。判 `P·A = L·U` 时**`P` 由 `piv` 独立重建**，不复用 LU 内部逻辑（否则等于自己验自己） |
| **`inverse`** | ① **五条求逆路径互不退化**（`lu`/`diagonal`/`cholesky`/`qr`/分发）② **结构快路径真的走了**（对角/正交/SPD 各落到对应分支）③ `Inverse(A, hint)` 与 `Inverse(A)` **结果必须一致**（`hint` 只跳过探测，不许改结果） |
| **`cholesky`** | ① SPD 判据的**本体**就是「Cholesky 走通」② 非正定/半正定/秩亏**必须 throw**（不许拿空矩阵当错误码）③ 与 LU 解对拍 |
| **`eigen`** | **Jacobi 的收敛与正交性**。重构 `max|A−QΛQᴴ|` + `‖QᴴQ−I‖` + `Σλ=tr(A)`（最后这条是独立不变量，不受实现路径影响） |
| **`svd`** | ① `AᴴA` 路线的**可信线**（`σ/σ_max ≳ 1e-6`，小 σ 只有 `√eps`）② **`Σσ²=‖A‖_F²`** —— 长方阵也成立的独立不变量 ③ 秩亏时 `U` 走正交补 ④ `σ` 非负降序 |
| **`qr`** | **三个分解各自正确**（Householder / Givens / MGS），不是只验其中一个。**且刻意不比 `Q`** —— 三个实现给出的 `Q` 差一个对角相位，`Q` 本身不可比；比的是 `Q·R=A` 与 `QᴴQ=I` |
| **`dual_complex`** | **泛型域最后一格**：`Dual<Complex<double>>` 从未被编译器碰过（「文件在」≠「能编译」的同族风险）。同时钉住「一个种子只给实雅可比一列」这条数学事实 |
| **`expm`** | ① **两条路线互为对照**（Taylor 级数 vs Padé `[13/13]` scaling-and-squaring）② **`det(exp X) = exp(tr X)`** 这条超强独立判据 ③ 幂零恒等式**判精确** |
| **`so3`** | ① `Hat` 的**符号**（恒等式抓不到整体翻号，必须靠六个非对角位置**逐位比对**）② `Cross` 对拍两条路径（手写三分量 vs `Matrix` 乘法）+ 与四元数纯虚积对拍 ③ **形状契约**：传错形状必须 throw，不许越界读 |
| **`smoke`** | 见 §1。**这是唯一一个「不判算法对错」的 linalg 用例** |

### 2.4 `quat/`（1 个）

| 用例 | 保护了什么 |
|---|---|
| **`quaternion`** | ① 基本代数 + Hamilton 积 ② **占位段钉住「其余入口仍不可用」** —— 这条机制的意义是：实现了没人知道，没实现也没人知道，所以用「断言它 throw」把它钉住。**实现一条就变红** |

### 2.5 一张图看这 17 个的强弱

**判据数量不代表强弱，但极端值有意义**：

```
svd        266  ← 判据最多：一条算法 × 实/复 × 方/长 × 各种秩
qr         189  ← 三个分解各跑一遍全套
eigen      119
cholesky    98
inverse     85  ← 五条路径 × 结构分支
quaternion  59  ← 含 10 项占位
smoke       56  ← 40 个入口 × 2 域，但每次只判一条
so3         51
scalar_traits 44
compute_graph 36
solve       34
backward    31
expm        25
tensor      24  ← 全占位
dual_complex 22
apply       18
jacobian    18
```

**`solve` 只有 34 项却最重要** —— 因为它是所有残差的**分母**。
判据数量和重要性无关，**位置才有关**。

## 3. 第 3 层：`apps/` 与 `pyapps/` —— 看现象

### 3.1 它们和第 2 层的分界（一条判定规则）

> **要不要出现在 ctest 的绿灯里？**
> 要 → `demo/<模块>/`（四行：`add_executable` + `target_include_directories` + `add_test`）
> 不要 → `demo/apps/`（三行：无 `add_test`，且**必须** `EXCLUDE_FROM_ALL`）

**`EXCLUDE_FROM_ALL` 是硬要求，不是风格**：`run_tests.sh` 构建走 `ALL`。
不加的话，附加区里的**半成品编译失败会把整个验收卡在构建阶段**，ctest 一条都跑不到。

### 3.2 `apps/` 现在有什么

| 程序 | 看的是什么现象 |
|---|---|
| `string_modes` | 离散 Laplacian 的特征值 → 连续算子谱 `(kπ)²`。**「矩阵 = 微分算子」的第一次实锤** |

**它的写法示范了 apps 层的正确形态**：
- 头部写清「连续问题 / 离散化 / 现象」三段
- **明写「现象（不是判据）」** —— 只打印比值随 N 收敛，不做阈值断言
- 用**已验收的** `eig_symmetric` 看现象（不是用未验收的代码）

### 3.3 `pyapps/` 是什么

纯 Python 数学演示（`sphere/` G 系列、`rotation/` R 系列），
`uv run` 跑，**不进 CMake / 不进 ctest**。

**它的定位**：**C++ 还没实现，但数学要先看见**。
所以它比 C++ 早 —— 例如 `R2` 里的四元数全套数学，早于 `quat/` 的实现；
而 `G` 系列的 `_core.py`（RK4 等）反过来是 `ode.hpp` 的**现成对拍源**。

**纪律（`pyapps/` 独有）**：
- **有图才算完**（每个切片 = 一个 `.py` + 一张图）
- LaTeX 必用 raw string `r"""..."""`（普通三引号会吃掉 `\t \v \b \f`）
- `.py` 里中文引号一律「」

## 4. 目录规范（加东西之前先读这一节）

### 4.1 命名：三者必须一致

```
文件名  ==  CMake 目标名  ==  ctest 用例名
```

**为什么**：`run_apps.sh` 靠**扫目录发现** app，靠**文件名**拼 target 名；
`run_tests.sh -d` 靠**ctest 名**逐项打印。三者不一致就会出现「构建出来但跑不到」
或「跑到了但不是你以为的那个」。

**现状**：17 个用例全部一致。**新增时保持**。

### 4.2 输出：两个标记是硬契约

```cpp
ck.check(pass, "名字");                     // 每项一行，含 [OK] 或 [FAIL]
...
return CheckReport(ck.ok, ck.fail, "标题");  // 末行汇总，返回 0/1
```

| 要求 | 硬/软 | 依据 |
|---|---|---|
| 每项判据输出一行，含 **`[OK]`** 或 **`[FAIL]`** | **硬** | `run_tests.sh -d` 用 `grep -c '\[OK\]'` 计数，缺了就统计不到 |
| 退出码 `0` 全绿 / `1` 有 FAIL | **硬** | ctest 判定 |
| 末行汇总「检查 N 项 (FAIL M)」 | 软（`CheckReport` 已给） | 便于人读 |
| 输出带 `got= / want=` 数值 | 软，**但强烈推荐** | **失败时信息量最大** —— 只给 `[FAIL] name` 你得回去加打印才能定位 |

**已知不一致（两处，待统一）**：`scalar_traits` 与 `compute_graph` 手写 `printf`，
格式是 `got=/want=`，**缺末行汇总**（所以 `grep '检查'` 数不到它们，`grep '[OK]'` 可以）。

**推荐改法**（改的是 `demo/common.hpp`，不是这两处）：
给 `Checker` 加一个带数值的变体，如 `ck.near(got, want, tol, name)`，
内部打印 `got=/want=` 并按 `tol` 判定。这样两种格式合一，且以后新用例不必手写 `printf`。

### 4.3 文件结构：头部注释是**判据规格书**

每个 `.cpp` 的头部注释顺序固定：

```
1. 一句话：本用例验收哪个头文件、对应哪条判据
2. 判据清单：①②③… 每条都要有【具体阈值】和【受什么保护】
3. 运行方式：./run_tests.sh 与单跑命令
```

**这不是格式要求，是流程要求**（`acceptance.md` §1「判据先行」）：
**先写「多少算对」，再对着判据写实现。** 反过来写等于「先写代码，再挑一个它的输出当标准」。

### 4.4 判据必须独立于实现路径

**禁止**：拿被测实现的输出当自己的参照。
**要求**至少一条下列判据（强度递减）：

1. **独立不变量**（`Σσ²=‖A‖_F²`、`Σλ=tr(A)`、`det(exp X)=exp(tr X)`）
2. **跨实现对拍**（两条独立代码路径 / 三个分解互比）
3. **解析对拍**（2×2 闭式解）
4. **重构**（`‖QR−A‖`）
5. **结构性**（精确 0 的位置必须精确 0）

### 4.5 异常与边界是必填项，不是加分项

每个用例**必须**含：

- **病态输入**：`n=0` / `n=1` / 近奇异 / 零阵 / 尺度悬殊
- **异常路径**：每种该抛的都验一遍，**且验异常类型**（`numeric-contract.md` §5）
- **判据函数与批量循环包 `try`** —— 异常会 `terminate` 整个用例（退出码 134），
  一个未捕获的 `throw` 会让**后面所有判据都不跑**

### 4.6 分域：实/复各实例化一次

`acceptance.md` §1 第 1 条：**模板 bug 只在实例化时暴露**。
「`double` 域 0 错」**掩盖**真 bug —— 这个仓已发生 **5 次，全在 `complex`**。
反向亦然：「编不过」可能只是域不匹配，不是真错。

## 5. 新增东西的最短路径

### 5.1 新增一个 ctest 用例

```bash
1. 在 demo/<模块>/ 建 xxx.cpp，头部按 §4.3 写判据规格书
2. 照抄同目录 CMakeLists.txt 的五行（add_executable / include / add_test）
3. ./run_tests.sh              # 确认新用例注册上了（应变成 18/18）
4. 在 ../test-map.md §2 的表里补一行（填【实测】判据数，见 §5.3）
```

### 5.2 新增一个 app（只看现象）

```bash
1. 在 demo/apps/ 建 xxx.cpp
2. CMakeLists.txt 加三行，**必须带 EXCLUDE_FROM_ALL**
3. ./run_apps.sh xxx
```

### 5.3 判据数别估算，跑一遍数

```bash
for t in core/scalar_traits linalg/svd ...; do
  echo "$t = $(./build/demo/$t 2>&1 | grep -c '\[OK\]')"
done
```

**必须用 `grep -c '\[OK\]'`，不能用 `grep '检查'`** ——
后者会漏掉 `scalar_traits` 和 `compute_graph`（它们没有末行汇总，见 §4.2）。

### 5.4 改了 `src/` 之后

**必跑全量，不许只跑改动那个用例。** 理由：
`Acceptance` 之间共享 `core/`（`scalar.hpp` / `matrix.hpp`），
改一处 `core` 可能让**全部**用例的阈值同时失效。

## 6. 常见错误（都是本仓真实发生过的）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **把 `.cpp` 放进 `apps/` 但注册了 `add_test`** | 半成品进验收，绿灯可信度下降 | 看 §3.1 的判定规则 |
| **`apps/` 忘了 `EXCLUDE_FROM_ALL`** | 整个 `run_tests.sh` 卡在构建阶段 | 硬要求 |
| **`.bak` / 临时文件放进 `demo/`** | 被 CMake 扫到（历史上真发生过一次） | 备份放 `.wip-*/`，不进源码目录 |
| **占位判据写成「跳过」** | 实现了没人知道，没实现也没人知道 | 写成「断言它仍然 `throw`」，实现一条就变红 |
| **只在 `[B]` 里调新入口** | 该入口的实例化依赖「有没有被用到」 | `[A]` 的 `EntryTable` 三处同步登记 |
| **判据用 `‖·‖∞` 判病态数据** | 1e9 与 1e-9 混在一起时，后者错 100% 也看不出来 | 逐元素判（`numeric-contract.md` §4.3） |

## 7. 目录一览（当前 42 个文件 + 本文）

```
demo/
├── common.hpp              ← 测试侧公共工具（量度 / 随机矩阵 / 记分板）。**不含被测实现**
├── CMakeLists.txt          ← 只有 5 行 add_subdirectory
├── core/        (3)        CMakeLists + scalar_traits  tensor
├── autodiff/    (5)        CMakeLists + compute_graph  apply  backward  jacobian
├── linalg/      (11)       CMakeLists + smoke  solve  inverse  cholesky  eigen  svd
│                           qr  dual_complex  expm  so3
├── quat/        (2)        CMakeLists + quaternion
├── apps/        (2)        CMakeLists + string_modes        ← 附加区，不注册 ctest
└── pyapps/      (17)       sphere/(8)  rotation/(8)  + tensor-convention.md
                                                             ← 纯 Python，不进 CMake
```

**注意 `linalg/` 是 11 个文件 = 1 个 CMakeLists + 10 个用例**。
上面 §2 说「linalg（9 个）」指的是**非 smoke 的专项用例**，两者差一个 `smoke`。

**目录本身就是文档**：`core/ autodiff/ linalg/ quat/` 一一对应 `src/` 下的同名目录。
**找不到某个算法的用例，就说明它没有验收** —— 这是最快发现覆盖漏洞的方法。
（反例：`src/math/` 目录不存在 ⇒ 没有对应 demo 目录 ⇒ 没有验收，一致。）
