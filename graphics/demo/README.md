## 1. 第 1 层：`smoke.cpp` —— 保护「编译」

### 1.1 它防的事故

2026-10-14 一次体检发现：**`linalg/` 528 行代码从未被任何编译单元 include 过**。
文件在、看着完整、文档写着「已落地」—— **但编译器从没看过它**。
模板代码的 bug 只在**实例化**时暴露，只 `#include` 抓不到。

**所以「已落地」的判定必须是「被某个 TU 实例化过」，而不是「文件存在」。**

### 1.2 它怎么保护

两段，**作用完全不同，不要合并**：

| 段 | 做法 | 保护什么 |
|---|---|---|
| **`[A]` 实例化闸门** | 对每个公开入口**取函数指针**（`&Fn<T>` ⇒ odr-use ⇒ 强制实例化），**刻意不调用** | 「每个入口都在 `double` 与 `Complex` 下各被实例化一次」。**独立于数值对不对** |
| **`[B]` 最小数值闸门** | 每个入口真跑一次，阈值 `1e-10` | 「跑得通 + 方向对」。**刻意比专项用例松** |

**为什么 `[A]` 要刻意不调用**：让「实例化」这件事和「数值正确」解耦。
如果只在 `[B]` 里调用，那么一个入口只要在 `[B]` 里没被用到，就等于没被实例化。

**三处登记，漏一处闸门静默失效**：`EntryTable` 一行 + `GateCount()` 一行 + `kEntryCount` 计数。
**这条规矩已被违反两次**，详见 `../test-map.md` §4.1（`expm_pade`、整个 `so3.hpp`）。

### 1.3 它保护不了什么

- **不覆盖 `quat/`**：四元数不在 `linalg`/`core` 的实例化范围内（`D16` 封死），
  由 `quat/quaternion.cpp` 自己保证。
- **不覆盖 `autodiff/`**：由 `scalar_traits` / `compute_graph` / `dual_complex` 覆盖。
- **不判算法精度**：`[B]` 的 `1e-10` 只证明「没写反」，不证明「精度够」。

## 2. 第 2 层：ctest 用例 —— 验证「算法对不对」

**17 个用例、1175 项判据、全绿。**
下表**只写「它坏了什么会悄悄出错」**，不写它怎么实现的。

### 2.1 `core/`（2 个）

| 用例 | 保护了什么 |
|---|---|
| **`scalar_traits`** | **整个库的地基**：同一份 `linalg` 源码能同时支持 `double` / `complex` / `Dual`。它坏了，报错会出现在模板深处（几百行之外），**极难定位**。含 `CommutativeScalar` 的 `a*b==b*a` 单测（这是「算法层零实复分支」的前提） |
| **`tensor`** | **哑容器契约不被破坏**。24 项全是「断言它仍然 `throw`」的占位 —— 实现一条就变红，红是提醒换真判据。**它保护的是「不许偷偷实现运算」** |

### 2.2 `autodiff/`（4 个）

| 用例 | 保护了什么 |
|---|---|
| **`compute_graph`** | **前向建图与求值的正确性**。图建错了，反向的梯度会「看起来能算」但全错 |
| **`apply`** | **`Apply` 的形状契约**（`D19` 分子布局）。历史上这里写错过：形状检查退化成恒真，导致**越界读**。它保护的是「形状不匹配必须报错，不许静默算」 |
| **`backward`** | **反向传播的伴随公式**。含最小闭环的**三方对拍**（解析 / 数值 / 图）—— 单靠一方都可能一起错 |
| **`jacobian`** | **雅可比是 m×n 分子布局、一次 sweep 填第 j 列**。布局翻案（`D19` 第二次修订）后，这是唯一的回归网 |

### 2.3 `linalg/`（9 个）

| 用例 | 保护了什么 |
|---|---|
| **`solve`** | **所有下游残差的分母**。`V1.2`–`V1.5` 的每个数字都出自 `LU + Solve` ——**它错了，后面每一步的残差都不值得信**。判 `P·A = L·U` 时**`P` 由 `piv` 独立重建**，不复用 LU 内部逻辑（否则等于自己验自己） |
| **`inverse`** | ① **五条求逆路径互不退化**（`lu`/`diagonal`/`cholesky`/`qr`/分发）② **结构快路径真的走了**（对角/正交/SPD 各落到对应分支）③ `Inverse(A, hint)` 与 `Inverse(A)` **结果必须一致**（`hint` 只跳过探测，不许改结果） |
| **`cholesky`** | ① SPD 判据的**本体**就是「Cholesky 走通」② 非正定/半正定/秩亏**必须 throw**（不许拿空矩阵当错误码）③ 与 LU 解对拍 |
| **`eigen`** | **Jacobi 的收敛与正交性**。重构 `max|A−QΛQᴴ|` + `‖QᴴQ−I‖` + `Σλ=tr(A)`（最后这条是独立不变量，不受实现路径影响） |
| **`svd`** | ① `AᴴA` 路线的**可信线**（`σ/σ_max ≳ 1e-6`，小 σ 只有 `√eps`）② **`Σσ²=‖A‖_F²`** —— 长方阵也成立的独立不变量 ③ 秩亏时 `U` 走正交补 ④ `σ` 非负降序 |
| **`qr`** | **三个分解各自正确**（Householder / Givens / MGS），不是只验其中一个。**且刻意不比 `Q`** —— 三个实现给出的 `Q` 差一个对角相位，`Q` 本身不可比；比的是 `Q·R=A` 与 `QᴴQ=I` |
| **`dual_complex`** | **泛型域最后一格**：`Dual<Complex<double>>` 从未被编译器碰过（「文件在」≠「能编译」的同族风险）。同时钉住「一个种子只给实雅可比一列」这条数学事实 |
| **`expm`** | ① **两条路线互为对照**（Taylor 级数 vs Padé `[13/13]` scaling-and-squaring）② **`det(exp X) = exp(tr X)`** 这条超强独立判据 ③ 幂零恒等式**判精确** |
| **`so3`** | ① `Hat` 的**符号**（恒等式抓不到整体翻号，必须靠六个非对角位置**逐位比对**）② `Cross` 对拍两条路径（手写三分量 vs `Matrix` 乘法）+ 与四元数纯虚积对拍 ③ **形状契约**：传错形状必须 throw，不许越界读 |
| **`smoke`** | 见 §1。**这是唯一一个「不判算法对错」的 linalg 用例** |

### 2.4 `quat/`（1 个）

| 用例 | 保护了什么 |
|---|---|
| **`quaternion`** | ① 基本代数 + Hamilton 积 ② **占位段钉住「其余入口仍不可用」** —— 这条机制的意义是：实现了没人知道，没实现也没人知道，所以用「断言它 throw」把它钉住。**实现一条就变红** |

### 2.5 一张图看这 17 个的强弱

**判据数量不代表强弱，但极端值有意义**：

## 3. 第 3 层：`apps/` 与 `pyapps/` —— 看现象

### 3.1 它们和第 2 层的分界（一条判定规则）

> **要不要出现在 ctest 的绿灯里？**
> 要 → `demo/<模块>/`（**三个 CMake 命令**：`add_executable` + `target_include_directories` + `add_test`）
> 不要 → `demo/apps/`（**两个命令**：无 `add_test`，且**必须** `EXCLUDE_FROM_ALL`）

**`EXCLUDE_FROM_ALL` 是硬要求，不是风格**：`run_tests.sh` 构建走 `ALL`。
不加的话，附加区里的**半成品编译失败会把整个验收卡在构建阶段**，ctest 一条都跑不到。

### 3.2 `apps/` 现在有什么

| 程序 | 看的是什么现象 |
|---|---|
| `string_modes` | 离散 Laplacian 的特征值 → 连续算子谱 `(kπ)²`。**「矩阵 = 微分算子」的第一次实锤** |

**它的写法示范了 apps 层的正确形态**：
- 头部写清「连续问题 / 离散化 / 现象」三段
- **明写「现象（不是判据）」** —— 只打印比值随 N 收敛，不做阈值断言
- 用**已验收的** `eig_symmetric` 看现象（不是用未验收的代码）

### 3.3 `pyapps/` 是什么

纯 Python 数学演示（`sphere/` G 系列、`rotation/` R 系列），
`uv run` 跑，**不进 CMake / 不进 ctest**。

**它的定位**：**C++ 还没实现，但数学要先看见**。
所以它比 C++ 早 —— 例如 `R2` 里的四元数全套数学，早于 `quat/` 的实现；
而 `G` 系列的 `_core.py`（RK4 等）反过来是 `ode.hpp` 的**现成对拍源**。

**纪律（`pyapps/` 独有）**：
- **有图才算完**（每个切片 = 一个 `.py` + 一张图）
- LaTeX 必用 raw string `r"""..."""`（普通三引号会吃掉 `\t \v \b \f`）
- `.py` 里中文引号一律「」

## 4. 目录规范（加东西之前先读这一节）

### 4.1 命名：三者必须一致

```
文件名  ==  CMake 目标名  ==  ctest 用例名
```

**为什么**：`run_apps.sh` 靠**扫目录发现** app，靠**文件名**拼 target 名；
`run_tests.sh -d` 靠**ctest 名**逐项打印。三者不一致就会出现「构建出来但跑不到」
或「跑到了但不是你以为的那个」。

**现状**：17 个用例全部一致。**新增时保持**。

### 4.2 输出：两个标记是硬契约，末行汇总不是

```cpp
ck.check(pass, "名字");                      // 每项一行，含 [OK] 或 [FAIL]
...
return CheckReport(ck.ok, ck.fail, "标题");   // 末行汇总，返回 0/1
```

| 要求 | 硬/软 | 依据 |
|---|---|---|
| 每项判据输出一行，含 **`[OK]`** 或 **`[FAIL]`** | **硬** | `run_tests.sh -d` 用 `grep -c '\[OK\]'` / `'\[FAIL\]'` 计数 |
| 退出码 `0` 全绿 / `1` 有 FAIL | **硬** | ctest 判定 |
| 末行汇总「检查 N 项 (FAIL M)」 | **软**（`CheckReport` 已给） | **`-d` 不依赖它** —— 那行数字是脚本自己算的，见下 |
| 输出带 `got= / want=` 数值 | 软，**但强烈推荐** | **失败时信息量最大** —— 只给 `[FAIL] name` 你得回去加打印才能定位 |

**实测的两种末行（15 : 2）**：

```
15 个用例（用 CheckReport）末行两行：      2 个手写 printf 的用例末行一行：
  svd: 检查 266 项 (FAIL 0)                 ALL TESTS PASSED (0 failures)
  ALL TESTS PASSED
```

**关键是别误解因果**：`run_tests.sh -d` 输出的「检查 N 项」是**脚本算的**，不是解析用例的末行：

```bash
n_ok="$(printf '%s\n' "$out" | grep -c '\[OK\]')"     # ← 脚本自己数
n_bad="$(printf '%s\n' "$out" | grep -c '\[FAIL\]')"
```

所以那两个手写 `printf` 的用例（`scalar_traits` / `compute_graph`）**在 `-d` 里照样显示 44 项 / 36 项**，
只是**单跑时**少一行汇总、可读性差一点。**这就是它只是"软要求"的原因。**

**推荐改法**（改 `demo/common.hpp`，不是改那两处）：
给 `Checker` 加一个带数值的变体，如 `ck.near(got, want, tol, name)` ——
内部打印 `got=/want=` 并按 `tol` 判定。这样两种格式合一，新用例不必手写 `printf`，
且失败时自动带数值。

### 4.3 文件结构：头部注释是**判据规格书**

每个 `.cpp` 的头部注释顺序固定：

```
1. 一句话：本用例验收哪个头文件、对应哪条判据
2. 判据清单：①②③… 每条都要有【具体阈值】和【受什么保护】
3. 运行方式：./run_tests.sh 与单跑命令
```

**这不是格式要求，是流程要求**（`acceptance.md` §1「判据先行」）：
**先写「多少算对」，再对着判据写实现。** 反过来写等于「先写代码，再挑一个它的输出当标准」。

**段编号 `[A]` `[B]` `[C]` 怎么用**：

多数用例内部按主题分段（`[A]` 重构 / `[B]` 正交性 / `[C]` 独立不变量…），
`ck.check()` 打印的名字里通常带段号（如 `"[B3] Q^H Q − I"`）。**它的作用是定位**：

```
看到 [FAIL] [D2] ...  →  回头部注释判据清单，找第 ④ 条对应的段
                     →  直接跳读该段的代码，不用整篇找
```

**约定（不是强制，但 17 个用例基本都这么做）**：
- `[A]` 一般是**主体判据**（重构 / 定义式）
- 靠后的段一般是**边界 + 异常**
- **`[P]` 段是占位** —— 只出现在 `tensor` 与 `quaternion`，语义是「断言它仍然 `throw`」
  （**不是"测过了"**，见 §2.4 与 §7 的占位说明）

有段号的用例读起来像**带索引的书**，没有段号的只能从头读 —— 这就是它值得保持的原因。

### 4.3.1 判据边界表（每段的必填附件）

判据清单回答「验什么」，边界表回答**「阈值多少、边界在哪、什么错误会被它抓住」**。
只有前者，半年后看到红灯无法判断是"实现坏了"还是"阈值该调了"。

**格式（跟着所属段一起写，不要单独成节）**：

```
//   [D] ② 逆与归一化 ───────────────────────────────────────────
//     判据        | 阈值            | 边界 / 病态输入        | 专抓什么错
//     ------------|-----------------|------------------------|------------------
//     D1 左右逆    | 1e-6 (绝对)      | **非单位** q,|q|=√30   | 只测一边漏一半代数
//     D2 q⁻¹ ≠ q*  | 差 > 1e-3        | 同上                   | 写死"只支持单位q"
//     G1 零四元数  | throw domain_error| 四分量精确全 0        | 用容差误判近零
```

三列的要求：

- **阈值**：写**数字**，不写"足够小"。相对/绝对要标明 —— `1e-8 相对` 与 `1e-8 绝对`
  在 `‖A‖=1e8` 时差 16 个数量级。
- **边界 / 病态输入**：必须列出该判据**实际喂了什么**。`n=0 / n=1 / 秩亏 / 尺度悬殊`
  这些是 `§4.5` 的硬要求，落到每一段就写进这一列。
- **专抓什么错**：这条最能防止判据退化。写不出来的判据 = 不知道自己为什么测它，
  通常可以删掉或换一条更具体的。

**为什么这一列非写不可**：本仓有过两次判据看起来全绿但抓不到错的事故 ——
`so3` 的 `Hat³ = −|u|²Hat` 抓不到整体翻号（两边都是奇次），`quaternion` 的
反交换/反自同构抓不到叉积符号写反（整体翻号抵消）。**只有注入对照能发现这种盲区**，
而盲区一旦写进"专抓什么错"这一列，下一个人就不会再误信它。

> 实例参考：`demo/quat/quaternion.cpp` 的「已知盲区」段、
> `demo/linalg/so3.cpp` 的 `[E]` 段注释、`demo/core/tensor.cpp` 的注入方案段。

### 4.4 判据必须独立于实现路径

**禁止**：拿被测实现的输出当自己的参照。
**要求**至少一条下列判据（强度递减）：

1. **独立不变量**（`Σσ²=‖A‖_F²`、`Σλ=tr(A)`、`det(exp X)=exp(tr X)`）
2. **跨实现对拍**（两条独立代码路径 / 三个分解互比）
3. **解析对拍**（2×2 闭式解）
4. **重构**（`‖QR−A‖`）
5. **结构性**（精确 0 的位置必须精确 0）

### 4.5 异常与边界是必填项，不是加分项

每个用例**必须**含：

- **病态输入**：`n=0` / `n=1` / 近奇异 / 零阵 / 尺度悬殊
- **异常路径**：每种该抛的都验一遍，**且验异常类型**（`numeric-contract.md` §5）
- **判据函数与批量循环包 `try`** —— 异常会 `terminate` 整个用例（退出码 134），
  一个未捕获的 `throw` 会让**后面所有判据都不跑**

### 4.6 分域：实/复各实例化一次

`acceptance.md` §1 第 1 条：**模板 bug 只在实例化时暴露**。
「`double` 域 0 错」**掩盖**真 bug —— 这个仓已发生 **5 次，全在 `complex`**。
反向亦然：「编不过」可能只是域不匹配，不是真错。

### 4.7 `common.hpp` 的三个量度函数，别用错

所有人共用的只有四个东西，**选错了会引入额外误差或量纲错**：

| 函数 | 是什么 | 用在哪 | 不能用在哪 |
|---|---|---|---|
| **`MaxAbs2(A)`** | `max \|a_ij\|²`（**平方量**） | **比较**（判据里的 `<=`） | 打印（读者看不出量级） |
| **`NormInf(A)`** | `sqrt(MaxAbs2)` = 真正的 ∞ 范数 | **打印 / 打分 / 报数** | **算法分支**（`D7`：判据只在实数域，且开方多一次舍入） |
| **`IsApprox(A,B,tol)`** | `MaxAbs2(A−B) <= tol*tol` | 矩阵相等判定 | 尺度悬殊的数据（见下） |
| **`RandMatrix<T>(r,c,seed,lo,hi)`** | 定 seed 随机阵，支持 `float`/`double`/`Complex`/`Dual`(含 `Dual<Complex>`) | 所有需要随机输入处 | 判病态（随机阵**不含**近奇异/尺度悬殊，要单独构造） |

**为什么比较用平方量**（`MaxAbs2`）而不是先开方：
阈值可以**预先平方**（`tol*tol`），**省一次 `sqrt`、也少一次舍入**。
两者数学等价，但 `MaxAbs2(A) <= tol*tol` 与 `sqrt(MaxAbs2(A)) <= tol` 在边界上可能差 1 ulp。

**量纲坑（`pitfalls.md` §八 ③ 同源）**：写成 `MaxAbs2(A) <= tol` 是把
「模长阈值」当「模长平方阈值」用 ⇒ **实际容忍度变成 `√tol`**，差一个数量级。
**见到 `abs2` 与 `tol` 同时出现，第一件事是看右边平方了没有。**

**`RandMatrix` 的三个必知**：

1. **seed 必须显式给**（默认 `1u`）。判据要可复现，同一 seed 两次跑必须逐位相同。
2. **它生成的是良态随机阵**，`lo/hi` 只是范围。近奇异、尺度悬殊、零阵、`n=0/1`
   **必须自己构造** —— 这是 §4.5「病态输入必列」的由来。
3. `Dual<Complex>` 的单列特化是**必需的**（`pitfalls.md` §五）：复用 `RandFill<Dual<U>>`
   会因 `Complex` 没有单参构造而编不过。

## 5. 怎么跑与怎么排障

> 这一节回答「绿灯是什么意思、红了怎么定位」。**不要跳过** ——
> 本仓历史上最浪费时间的事故是「用错的方式验证」，比如跑的还是上一次的二进制。

### 5.1 三个入口，各管一段

| 入口 | 跑什么 | 什么时候用 |
|---|---|---|
| `./graphics/scripts/fetch_deps.sh` | 下载/校验 C++ 依赖 + 装 Python 工具 | **新机器第一次**，或 `cmake` 报「找不到 googletest」 |
| `./graphics/run_tests.sh` | **配置 + 构建 + 全部 17 个 ctest** | 每次改完 `src/` 或 `demo/`，**收工前必跑** |
| `./graphics/run_tests.sh --coverage` | 同上 + gcovr 报告（见 §5.6） | 想知道「哪些行从没被执行过」 |
| `./graphics/run_apps.sh <name>` | 构建 + 跑一个 app（`demo/apps/`） | 只想看现象 |
| `./graphics/build/demo/<模块>/<名>` | 直接跑单个用例，**不重新构建** | 已知只改了一个用例，想反复看明细 |

**三者关系**：`run_tests.sh` 是**唯一权威**（它管构建）。
后两个都**假定已经构建过** —— 改了代码不重跑 `run_tests.sh` 直接单跑，
**跑的是旧二进制**（`pitfalls.md` §九 ① 记的就是这个坑的变体）。

### 5.2 选项表（都实测过）

**`run_tests.sh`**

| 选项 | 作用 |
|---|---|
| （无参） | 增量构建 + 跑全部 |
| **`-d`** | 跑完再逐用例打印统计 + 末行。**定位时最常用**。注意两套框架数的不是一回事：老用例显示「**断言** N 项」，gtest 显示「**用例** N 个」，**两列不可横比**（见 §5.7） |
| `-c` | 删掉构建目录从零构建（怀疑缓存时用） |
| `-w` | 开 `-Wall -Wextra`。**查"编得过但不对劲"时用** |
| `-j 4` | 并行度（默认本机核数） |
| `-b /tmp/gb` | 换构建目录 |
| `-l` | 只列出已注册用例，不构建不跑（**查"用例注册上了没"**） |
| `--build-only` / `--test-only` | 只构建 / 只跑测试 |
| **`--coverage`** | 插桩构建 + 跑测试 + 出 gcovr 报告；构建目录默认 `build-cov` |

**`run_apps.sh`**：`<name>` 构建并跑；`<name> -c` 从零；`<name> -- 3 7` 把参数透传给 app。

### 5.3 退出码有两套，别混

| 谁 | 退出码 |
|---|---|
| **单个用例**（`CheckReport` 返回） | `0` 全过 / `1` 有 FAIL。ctest 靠这个判红绿 |
| **`run_tests.sh`** | `0` 全绿 / `1` **配置或构建失败** / `2` **有用例失败** / `64` 参数错误 |

**区别很实用**：
- 退出码 `1` ⇒ **一条用例都没跑**，问题在 CMake 或编译器
- 退出码 `2` ⇒ 构建成功但有用例红，问题在代码或判据
- 单跑时出现 `134`（SIGABRT）⇒ **判据函数没包 `try`**，异常 terminate 了进程

### 5.4 红了怎么定位（按这个顺序）

```
① 看退出码
   ├─ 1 → 配置/构建失败：读编译错误。常见原因是漏 target_include_directories
   │      或 apps/ 里漏了 EXCLUDE_FROM_ALL（半成品参与 ALL 构建）
   ├─ 2 → 有用例失败：进 ②
   └─ 134（单跑）→ 判据函数没包 try

② 跑 ./run_tests.sh -d
   ├─ 只有 1 个用例红 → 进 ③
   ├─ 全部红        → 改过 core/（scalar.hpp / matrix.hpp）？
   │                  共享依赖坏了，全部阈值会同时失效，先修那一处
   └─ 时好时坏      → 未定义行为：越界读 / 未初始化。
                      ./run_tests.sh -w 看告警；再单跑几次看结果是否变

③ 单跑那个用例，找 [FAIL] 那一行的名字
   → 回该用例头部注释的「判据 ①②③」清单，看它属于哪一条
   → 按那一类的性质判断（见下）

④ 判断是实现错还是判据病态
   ├─ ① 结构性（要求精确 0）红 → 几乎一定是实现错
   ├─ ③ 独立不变量红 → 先查量级（numeric-contract.md §4.2 的阈值分级表）
   └─ 拿不准 → 查 pitfalls.md §一「判据病态 ≠ 实现错」
```

**一条经验**：`[FAIL]` 的名字是**手写的字符串**，多数用例已经在名字里带了数值
（如 `"V1.2 求逆残差 1.18e-13 < 1e-8"`）—— **先读名字，它经常直接告诉你答案**。

### 5.5 构建成功但 `-l` 看不到新用例

三个可能，按顺序查：

1. **`add_test` 漏了** —— 只有 `add_executable` 时程序会构建出来，但 ctest 不认识它
2. **`demo/CMakeLists.txt` 没 `add_subdirectory(<新目录>)`**
3. **改了 `CMakeLists.txt` 但没重新配置** —— `run_tests.sh` 会配置，但如果直接
   `cmake --build` 就不会。用 `run_tests.sh -c` 彻底重来

### 5.6 覆盖率：看「未解释行」，不看百分比

```bash
./graphics/run_tests.sh --coverage      # 构建目录默认换成 build-cov，不污染日常构建
```

**分母只算 `src/`**（`demo/` 是判据本身，算进去等于把"测试写了多少行"当覆盖率）。

**这个百分比不是质量指标。** 模板未实例化的分支天然是 0%，`--coverage` 下
分支覆盖率长期在 35% 上下，不代表库只测了三分之一。正确用法只有一种：

> **每一行未覆盖，必须能说出属于下面三类中的哪一类；说不出来就是缺判据。**

| 未执行的原因 | 合法？ | 处理 |
|---|---|---|
| 模板分支未被任何域实例化 | 合法，但**必须登记** | 进 `../test-map.md` 的「未实例化清单」，与 §4.1 闸门漏项同一张表 |
| 契约性 throw（正常路径不该触发） | 合法 | 应被 `[G]` 段的 `EXPECT_EXACT_THROW` 覆盖；覆盖不到 = 契约用例缺一条 |
| 死代码 / 到不了的防御分支 | **不合法** | 删掉，或补一条注入对照证明它可达 |

2026-10-30 首次实测（`-O0 -fno-inline --coverage`，AppleClang 17 + gcovr 8.8）：
行 **79.2%**、分支 35.7%、函数 89.8%。**这三个数只作基线，不作目标。**

工具链：`gcov`（系统自带）+ `gcovr`（`./graphics/scripts/fetch_deps.sh` 装）。
若 gcovr 报解析错误，多半是 AppleClang 的 `.gcda` 与 `gcov` 版本不匹配 —— 见该脚本头注释。

**`--coverage` 默认从零重建 `build-cov`，不要关掉这个行为。**
`.gcda` 会跨次累积，被测代码或框架变过之后再复用旧目录，数字会**静默失真**：
2026-10-30 把 `quaternion.cpp` 从老框架迁到 gtest 之后，增量跑出来的
`src/quat/quaternion.hpp` 覆盖率是 **5%**，而从零重建是 **96%**。
假的低值会让人去补根本不缺的判据 —— 比没有覆盖率更贵。
（想增量跑就显式 `-b <dir>`，此时口径由你负责。）

### 5.7 两套框架并存：gtest 与老 Checker

2026-10-30 起 `demo/` 里两种写法共存，**一个文件只准用其中一种**：

| 写法 | 注册函数 | 长什么样 |
|---|---|---|
| gtest | `graphics_add_gtest(<名>)` | `TEST()` / `TYPED_TEST()`，**不写 `main`** |
| 老写法 | `graphics_add_legacy_test(<名>)` | 自己带 `main` + `Checker` 计分板 |

迁移期规矩（不是为了整洁，是为了不把牙拔掉）：

1. **逐文件迁移**。每迁完一个，必须把它在**「判据边界表」里记的注入对照重跑一遍**，
   确认新框架仍抓得住同一个 bug，再动下一个。抓不住就地回退 ——
   迁完不验，等于用「看起来是测试」换掉「真的能抓错」。
2. **不许 `FetchContent`**。依赖预下载（`graphics/scripts/fetch_deps.sh` +
   `graphics/deps.manifest` 里 pin 的 sha256）。构建期联网 ⇒ 不可复现。
3. **异常判据只用 `EXPECT_EXACT_THROW`**（在 `gtest_common.hpp`）。
   直接写 `EXPECT_THROW(stmt, std::logic_error)` 会被 `invalid_argument` /
   `out_of_range` 冒充 —— 那是假绿。
4. **`tensor.cpp` 不单独迁移**。它的 24 条 `[P]` 是「断言仍 throw」的占位，
   先迁到 gtest 再实现等于写两遍 —— 迁移与实现合并做。

**`-d` 明细模式两套都认**：`run_tests.sh` 第 5 段用正则同时匹配
`[OK]`（老）与 `[       OK ]`（gtest，带空格填充）。只写 `\[OK\]` 会让 gtest 用例
恒为「检查 0 项」且**不报错** —— 这是静默失效，与 `smoke` 漏登记同类。

## 6. 新增东西的最短路径

### 5.1 新增一个 ctest 用例

```cmake
# demo/<模块>/CMakeLists.txt —— 三个命令，缺 add_test 就进不了 ctest
add_executable(xxx xxx.cpp)
target_include_directories(xxx PRIVATE ${GRAPHICS_SRC_DIR})
add_test(NAME xxx COMMAND xxx)
```

```bash
1. 建 demo/<模块>/xxx.cpp，头部按 §4.3 写判据规格书
2. 上面三个命令（照抄同目录已有条目；文件名 = target 名 = ctest 名）
3. ./run_tests.sh              # 确认注册上了（总数会 +1）
4. 在 ../test-map.md §2 的表里补一行（填【实测】判据数，见 §6.3）
```

### 5.2 新增一个 app（只看现象）

```bash
1. 在 demo/apps/ 建 xxx.cpp
2. CMakeLists.txt 加三行，**必须带 EXCLUDE_FROM_ALL**
3. ./run_apps.sh xxx
```

### 5.3 判据数别估算，跑一遍数

```bash
for t in core/scalar_traits linalg/svd ...; do
  echo "$t = $(./build/demo/$t 2>&1 | grep -c '\[OK\]')"
done
```

**必须用 `grep -c '\[OK\]'`，不能用 `grep '检查'`** ——
后者会漏掉 `scalar_traits` 和 `compute_graph`（它们没有末行汇总，见 §4.2）。

### 5.4 改了 `src/` 之后

**必跑全量，不许只跑改动那个用例。** 理由：
`Acceptance` 之间共享 `core/`（`scalar.hpp` / `matrix.hpp`），
改一处 `core` 可能让**全部**用例的阈值同时失效。

## 7. 常见错误（都是本仓真实发生过的）

| 错误 | 后果 | 正确做法 |
|---|---|---|
| **把 `.cpp` 放进 `apps/` 但注册了 `add_test`** | 半成品进验收，绿灯可信度下降 | 看 §3.1 的判定规则 |
| **`apps/` 忘了 `EXCLUDE_FROM_ALL`** | 整个 `run_tests.sh` 卡在构建阶段 | 硬要求 |
| **`.bak` / 临时文件放进 `demo/`** | 被 CMake 扫到（历史上真发生过一次） | 备份放 `.wip-*/`，不进源码目录 |
| **占位判据写成「跳过」** | 实现了没人知道，没实现也没人知道 | 写成「断言它仍然 `throw`」，实现一条就变红 |
| **只在 `[B]` 里调新入口** | 该入口的实例化依赖「有没有被用到」 | `[A]` 的 `EntryTable` 三处同步登记 |
| **判据用 `‖·‖∞` 判病态数据** | 1e9 与 1e-9 混在一起时，后者错 100% 也看不出来 | 逐元素判（`numeric-contract.md` §4.3） |
| **手写 `printf` 时漏了 `[OK]`/`[FAIL]` 标记** | `run_tests.sh -d` 数到 **0 项**，看着像"没跑" | 标记是硬契约（§4.2）；能不用手写就别手写 |
| **新增用例忘了 `add_subdirectory`** | 目录里的东西压根不参与构建，`-l` 看不到 | 三处都要：`.cpp` + 目录 CMakeLists + 父 CMakeLists |
| **`abs2(...) <= tol`（右边没平方）** | 实际容忍度变成 `√tol`，差一个数量级 | `abs2(...) <= tol*tol`（`pitfalls.md` §八 ③） |
| **判据函数/批量循环没包 `try`** | 一次 `throw` ⇒ `terminate` ⇒ **后面所有判据都不跑**，退出码 134 | 每个判据包 `try`，`catch` 里记 FAIL 继续 |

## 8. 目录一览（当前 43 个文件，含本文）

```
demo/                                       (43)
├── README.md               ← 本文（导读与规范）
├── common.hpp              ← 测试侧公共工具（量度 / 随机矩阵 / 记分板）。**不含被测实现**
├── CMakeLists.txt          ← 只有 5 行 add_subdirectory
├── core/        (3)        CMakeLists + scalar_traits  tensor
├── autodiff/    (5)        CMakeLists + compute_graph  apply  backward  jacobian
├── linalg/      (11)       CMakeLists + **10 个 .cpp**：
│                             smoke  solve  inverse  cholesky  eigen  svd
│                             qr  dual_complex  expm  so3
├── quat/        (2)        CMakeLists + quaternion
├── apps/        (2)        CMakeLists + string_modes        ← 附加区，不注册 ctest
└── pyapps/      (17)       sphere/(8)  rotation/(8)  + tensor-convention.md
                                                             ← 纯 Python，不进 CMake
```

**两处容易数错的**：

- 根目录 **3 个文件** = 本文 + `common.hpp` + `CMakeLists.txt`
- `linalg/` **11 个文件** = 1 个 CMakeLists + **10 个 `.cpp`**。
  而 §2.3 标题写「9 个」指的是**非 smoke 的专项用例** —— 10 个 `.cpp` 里 `smoke` 是闸门，
  它与其余 9 个的性质不同（§1 讲的就是它）。**别把这两个数字当成矛盾。**

**目录本身就是文档**：`core/ autodiff/ linalg/ quat/` 一一对应 `src/` 下的同名目录。
**找不到某个算法的用例，就说明它没有验收** —— 这是最快发现覆盖漏洞的方法。
（反例：`src/math/` 目录不存在 ⇒ 没有对应 demo 目录 ⇒ 没有验收，一致。）
