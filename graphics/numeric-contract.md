## 2. D7：数值判据只在实数域发生

**契约三条**：

1. **比较一律走 `abs2`**，不比较 `T` 本身（`Complex` 无全序，`Dual` 比较无意义）。
   需要真实 ∞ 范数时才 `sqrt`，且**只在打印/打分路径**，不进算法分支。
2. **共轭走 `ScalarTraits<T>::conj`**，算法层写 `x * conj(y)` 而不是 `if constexpr (is_complex)`。
   实复差异**只存在于 traits 特化**，算法层零分支（呼应 `acceptance.md` 红线 #1）。
3. **取实部走 `ScalarTraits<T>::real(x)`**，判据函数内部统一 `double(real(x))` 再比。
   源码里 `demo/linalg/svd.cpp:41` 的 `Re()` 就是这个口径。

**为什么这条重要**：`Dual<T>` 的「比较」会退化成比 value 槽，`Complex<T>` 无全序。
一旦在算法层写 `a < b`，模板在 `Dual` 域实例化时**要么编不过、要么静默比错的槽**。
后者更危险——`acceptance.md` §1 第 1 条「分域探针」记录的 5 次事故全属此类。

**已知盲区（必须知道）**：`abs2` 会把相位信息扔掉。两个**仅差相位**的复数被判为相等。
所以**不能**用 `abs2` 判「复向量是否相同」，只能判「模长是否相同」——
判复向量相同要逐分量比 `real` 与 `imag` 两个槽。

## 3. D12：除零两层 + 容差显式

这是 `matrix.md` 删掉后最容易失传的一条，**完整写在这里**。

### 3.1 两层约定（核心）

| 层 | 谁 | 行为 | 依据 |
|---|---|---|---|
| **第 1 层：标量层** | `Complex::operator/`、`Matrix` 逐元素除 | **不判、不抛**，让 IEEE 的 `inf`/`NaN` 沿运算传播 | `src/core/complex.hpp:46` |
| **第 2 层：算法层** | `LU` / `Inverse` / `cholesky` / `diagonal_inverse` / `qr_inverse` | **显式判 `|pivot| <= tol`，抛 `runtime_error`** | `src/linalg/{solve,inverse,cholesky,qr}.hpp` |

**为什么必须分两层，不能统一成一层**：

- **标量层判不了**：单次除法只知道分母是不是 0，**不知道整个矩阵是否可逆**。
  在标量层判 0 会把「中间量恰好为 0 但整体可解」的情况误杀。
- **算法层才知道该判什么**：`LU` 判的是**主元**（选主元后的 `|p|`），不是原始元素。
  在错误的量上判，等于判了个无关的东西。

**推论（容易踩）**：标量层不抛 ⇒ **`NaN` 会流到算法出口**。
所以**每一个有奇异可能的算法入口都必须自己判**，不能指望下层抛。
新增算法入口时，这一条是必查项（见 §8 检查表）。

### 3.2 容差必须由调用方显式给

`is_diagonal` / `is_symmetric` / `is_orthogonal` / `Classify` / `diagonal_inverse` 等
**结构探测与快路径入口**，容差是**参数**，不是内部默认值：

```cpp
bool is_diagonal(const Matrix<T>& A, typename ScalarTraits<T>::real_t tol);
Matrix<T> diagonal_inverse(const Matrix<T>& A, typename ScalarTraits<T>::real_t tol);
```

**理由**：同一份代码要在不同尺度上用。判「这个矩阵是否对角」时，
`tol = 1e-12`（严格）和 `tol = 1e-6`（容忍工艺误差）都可能正确，**取决于调用场景**。
写死默认值就是把一种场景的判断强加给所有场景。

**唯一的全局默认值是 `DefaultTol<T>(n)`**，见 §4.1。

### 3.3 例外：四元数求逆只判**精确 0**

`Quaternion::Inverse()` 的约定与矩阵求逆**不同**，必须分开记：

| | 判据 | 理由 |
|---|---|---|
| 矩阵求逆 | `|pivot| <= DefaultTol(n)` | 近奇异时**结果无意义**（条件数爆炸），必须拒 |
| **四元数求逆** | **只判 `SquaredNorm() == 0`（精确 0）** | 近零四元数**仍然可逆**（逆模长很大但正确）；用 `DefaultTol` 判会把**合法输入拒掉** |

源码原文（`src/quat/quaternion.hpp:131`）：

> 建议**只对精确 0 抛**，不要带容差：近零四元数仍然可逆（只是逆很大），
> 用 `DefaultTol` 判会把合法输入拒掉。

**为什么四元数能承受近零**：它是**标量除法**，`1/ε` 数值上大但仍精确；
矩阵求逆要解方程组，近奇异时舍入被条件数放大，结果**不是"大"而是"错"**。

**还有一条**：单位四元数下有捷径 `q^{-1} = q*`，但**别写死成「只支持单位四元数」**——
`Slerp` 的中间量与 `FromMatrix` 的原值都可能**暂时不是单位长度**。

## 4. 容差体系（本仓实测阈值，不是教科书抄的）

### 4.1 `DefaultTol<T>(n)` 的定义与三个必须知道的点

```cpp
// src/core/scalar.hpp:123
template <typename T>
typename ScalarTraits<T>::real_t DefaultTol(int n)
{
    return real_t(8) * real_t(n) * std::numeric_limits<real_t>::epsilon();
}
```

**① 系数 8 与因子 `n` 都是必需的**。`8n·eps` 的量级是「n 次累加的最坏舍入」。

**② 绝不能换成全局常数**（源码注释明确记录过这个错）：

| 类型 | `epsilon()` | 差 |
|---|---|---|
| `float` | `1.19e-7` | |
| `double` | `2.22e-16` | **9 个数量级** |

用全局 `Tol`（通常是 float 的 eps）判 double 的奇异性，会**把良定矩阵误判成奇异**。

**③ `DefaultTol` 是「唯一性/失败」判据，不是「秩」判据**。
用 `8n·eps` 判秩亏历史上只对 **73/100**（见 `acceptance.md` §1 第 4 条与下文 §4.3）。

### 4.2 阈值分级表（按「离机器精度几步」定，不是拍脑袋）

| 判据类型 | 实测阈值 | 出现在 | 为什么是这个量级 |
|---|---|---|---|
| **正交性 / 酉性** `‖Q^H Q − I‖∞` | **1e-12** | eigen / svd / qr | 只有 O(n) 次累加，几乎就是 `n·eps` |
| **重构** `‖Q·R − A‖∞`、`‖L·L^H − A‖∞`、`‖UΣV^H − A‖∞` | **1e-8** | cholesky / eigen / svd / qr | 含 O(n³) 运算 + 算法收敛精度 |
| **求逆残差** `‖A·A⁻¹ − I‖∞` | **1e-8** | inverse | 条件数已进入结果 |
| **解残差** `‖A·X − B‖∞ / (1+‖B‖∞)` | **1e-10** | solve / cholesky | 分母归一化后比原始残差更严 |
| **跨实现一致** value / derive | **1e-12 / 1e-10** | dual_complex | 同一算法的两条路径，derive 多一次累加 |
| **smoke 轻量闸门** | **1e-10** | smoke `[B]` 段 | **刻意比专项用例松**（只判"跑得通 + 方向对"） |

**读法**：阈值不是「越严越好」。
- 把正交性判到 1e-15 → 随机矩阵上**必然假 FAIL**（`n·eps` 就超过它）
- 把重构判到 1e-12 → 会把**算法收敛精度**当成 bug

**修阈值前先问**：这条判据里有多少次浮点运算？结果量级是多少？**没算过就不许改**。

### 4.3 病态数据的额外口径

1. **`‖·‖∞` 相对误差会低估问题**。`A` 里同时有 `1e9` 与 `1e-9` 时，
   后者错 100% 也只贡献 `1e-18` 的相对变化 ⇒ **病态数据必须逐元素判，不能只判范数**。
2. **`DefaultTol` 判秩只对 73/100**，秩判定要用 **`√eps` 级**阈值。
   区别：`DefaultTol` 问「这个值是否**唯一**确定」，秩判定问「这个值是否**本质为 0**」。
3. **SVD 可信线 `σ_i/σ_max ≳ 1e-6`**，`< 1e-8` 一律当 0 —— 因为本库走 `A^H A`，
   **条件数被平方**，小奇异值只有 `√eps` 精度。
4. **`expm` 判据必须相对**（元素量级是 `e^‖A‖`）。绝对差历史上报过 **`1.1e+29` 假 FAIL**。

### 4.4 判据自身可能病态（与实现无关）

| 病态判据 | 症状 | 换用 |
|---|---|---|
| `acos((tr(R)−1)/2)` 量旋转角 | θ→0/π 时导数发散，给 1e-8 **假误差** | `atan2(‖vee(R−R^T)‖/2, (tr−1)/2)` |
| 恒等式抓符号翻转 | `Hat³ = −|u|²Hat` 与 `Vee∘Hat = id` **两边同奇次，翻号抵消** | 六个非对角位置**逐位比对** + `Cross` 对拍 |

**这是 `acceptance.md` §1 第 4 条那个"判据可能自身病态"的完整案例集**。
遇到「实现明明对但判据红」时，先怀疑判据，再怀疑实现。

## 5. 错误类型语义（三种，不能混用）

代码里到处 `throw`，但**抛哪一种是有约定的**。混用会让调用方无法区分
「我传错了」和「数学上没有解」。

| 异常类型 | 语义 | 触发条件 | 例子 |
|---|---|---|---|
| `std::invalid_argument` | **调用方的错**：参数在**语义上**就不合法 | 非方阵、空矩阵、`m < n`（thin QR）、形状不符、行数不匹配 | `"LU: A 必须是方阵"`、`"Cross: 入参必须是两个 3x1 列向量"`、`"QR_Householder: 需要 m >= n (thin QR)"` |
| `std::runtime_error` | **输入的错**：参数合法但**数值上做不到** | 奇异 / 近奇异 / 非正定 / 迭代不收敛 | `"LU: 主元近奇异 (判据 |p| <= tol)"`、`"cholesky: A 非正定或近奇异"`、`"eig_symmetric: Jacobi 迭代 …"` |
| `std::logic_error` | **实现的错**（本该永不发生） | 未实现的分支、不可达逻辑 | `"Inverse: RigidTransform 分支未实现"`、`"Inverse: 未覆盖的 MatrixKind"` |

**三条使用规则**：

1. **`invalid_argument` 与 `runtime_error` 的分界是「换个输入能不能成功」**。
   非方阵换个矩阵就好了（调用方问题）；奇异矩阵说明这组数据无解（输入问题）。
   **调用方需要区分这两者**：前者是 bug，后者是可预期的失败路径。
2. **`logic_error` 表示「这不该发生」**。它出现在 `switch` 的 `default` 分支或未实现入口。
   **生产路径上出现 `logic_error` 就是 bug**，不要 `catch` 它继续跑。
3. **不拿「空矩阵 / 0×0」当错误码**。`D12` 相关记录明确：
   `0×0` 走 `invalid_argument` 显式抛，**不返回空矩阵表示失败**
   （静默返回是 `acceptance.md` §0.6 反例 N4「失败时静默返回错误结果」）。

**必查清单**：每个公开入口至少要有
- 一条**形状检查**（`invalid_argument`）
- 一条**数值检查**（`runtime_error`）—— 若该算法有奇异可能

`demo/linalg/smoke.cpp` 的 `[A]` 段只保证「能实例化」，**不保证这两条存在**。
哪条缺失，见 `test-map.md` §4 的覆盖表。

## 6. D19：布局与形状契约

**全库统一口径**（第二次修订 2026-10-19，此前是分母布局）：

| 对象 | 约定 |
|---|---|
| **向量** | **n×1 列向量**（不是 1×n 行向量） |
| **线性映射** | `y = W·x`，`W` 是 m×n |
| **雅可比** | `J_ij = ∂y_i/∂x_j`，形状 **m×n**（行 = 输出，列 = 输入） |
| **链式法则** | 自然序 `J_{f∘g} = J_f·J_g`（旧口径是镜像的 `J_g·J_f`） |
| **标量输出的 J** | **1×n 行**；梯度 = `J^T` 是 n×1，与被微对象同形 |
| **`Jacobian(f,x)` 填法** | 一次 sweep 填**第 j 列** |

**三个由它派生的硬约束**：

1. **形状契约必须逐维比，不能只比一个维度**。
   历史 bug：`Apply` 的形状检查写成 `A.Cols() != f.Cols()`，在列向量下**退化成恒真**，
   导致越界读。**必须 `Rows()` 与 `Cols()` 都比**（1×1 广播除外）。
2. **`so3.hpp` 的入参出参一律 3×1 列向量**，形状不对 `throw invalid_argument`，
   **不静默接受**。`Hat` 绝不归一化（`hat(λu) = λ·hat(u)` 是线性的，θ 要乘在外面）。
3. **转置 = 伴随，不是改行列布局**。
   `A^T` 的定义是 `⟨A^T u, v⟩ = ⟨u, A v⟩`。换度量后是 `G⁻¹A^T G`。
   梯度上冒转置的原因是：按雅可比定义 `df` 是 **1×n 行**，
   把梯度写成列 `∇f = (df)^T` **本身就付了一次转置** —— 与布局约定无关。

**`det J = 1` 不够、`J` 对称也不够**：只有 `J` **正交**时 `J^{-T} = J` 才无感。

## 7. 泛型域契约（`double` / `Complex` / `Dual` 同源）

呼应 `acceptance.md` 红线 #1 与 #5。这一节是**编译期**约束，不是运行期。

### 7.1 `real_t` 与 `T` 不能直接相乘

```cpp
// 错：real_t * T 没有定义
// 对：
ScalarTraits<T>::fromReal(x) * y
```

`Dual<Complex>` 的字面量必须是 `DC(C(0,0), C(0,0))`，不能写 `0.0`。

### 7.2 随机填充需要单列特化

`RandFill<Dual<Complex<U>>>` **必须单列一条**，不能复用 `RandFill<Dual<U>>`。
原因（`demo/common.hpp:88-92` 实测记录）：那里写 `static_cast<U>(a)`，
`U = Complex<U'>` 时 **`Complex` 没有单参构造**，报
`no matching conversion for static_cast from 'double' to 'Complex<double>'`。

### 7.3 D16：四元数封死

- **不进 `Matrix<Quaternion<T>>`** ⇒ **不需要** `ScalarTraits<Quaternion<T>>`
  （`zero`/`one`/`fromReal`/`conj`/`abs2` 一整套都不欠）。
- **`quat/` 不 include `linalg/so3.hpp`**：`operator*` 与 `Rotate` 里的叉积**手写三行**。
  **这是故意的重复**，已在头文件注释钉死 —— 为 3 行算术引入跨层依赖不划算，
  且会让 `so(3)` 反向依赖 `quat`。**别来"去重"。**
- **demo 层不受此约束**（`demo/linalg/so3.cpp` 的 `[F]` 段就用四元数对拍 `Cross`）。

### 7.4 `Matrix` 的运算符限制（写模板时会撞上）

| 表达式 | 有吗 |
|---|---|
| `Matrix * T` | ✅（成员重载） |
| `T * Matrix` | ❌ |
| `Matrix / T` | ❌（只有 `cwiseDivision`） |
| `Matrix += Matrix` | ✅（只有 `+=`） |
